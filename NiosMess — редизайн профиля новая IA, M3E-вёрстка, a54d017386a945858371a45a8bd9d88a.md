# NiosMess — редизайн профиля: новая IA, M3E-вёрстка, готовый код

Контекст: HEAD `d7c739bf`, версия `3.60.7+143`. Анимации переключения табов в скоуп не входят — они уже в работе отдельной задачей.

Задача двойная: убрать из профиля навигационный мусор (раздел «Nios ID», который выбрасывает в браузер, и карточку «Все настройки») и **одновременно наполнить экран реальным содержимым**, чтобы после чистки не осталась плашка сверху и пустота.

## 1. Что не так сейчас

1. **Профиль — это меню меню.** Ниже «Графика работы» нет ни одного собственного элемента: шестерёнка в баре, карточка «Все настройки» и раздел «Nios ID» — три входа в навигацию и ноль контента.
2. **Шеврон обманывает.** У тайла «Управление аккаунтом Nios ID» стоит `>`, который обещает переход внутри приложения, а по факту `launchUrl(..., mode: LaunchMode.externalApplication)` выбрасывает в Chrome. В `settings_account_screen.dart` та же ссылка помечена правильно — `Icons.open_in_new_rounded`. Приложение противоречит само себе на одном действии.
3. **Это дубликат.** В Настройки → Аккаунт уже есть: Nios ID как значение, активные сессии нативным экраном (`/settings/sessions`), тумблер биометрии и та же ссылка `https://ni-os.ru/id/account`. Подпись на профиле обещает «Безопасность, 2FA и активные сессии» — два из трёх пунктов нативные и живут в другом месте.
4. **Белая карточка на розовом фоне** с тенью — единственный чисто белый элемент экрана, выбивается из тональной палитры (подробности в дизайн-аудите).
5. **Три входа в редактирование**: карандаш в баре, карандаш в «Графике работы», кнопка «Редактировать профиль».

## 4. Чем именно заполняется экран

| Блок | Источник данных | Статус |
| --- | --- | --- |
| Имя, @ник, аватар, био | `authProvider.profile` / `session` | есть |
| Бейджи | `ApiBadge`  • `badge_selector_dialog.dart` | есть |
| Nios ID | `auth.session?.niosId` | есть |
| Телефон, дата рождения | `authProvider.profile` | есть |
| График работы | `working_hours_widget.dart` | есть |
| AI-токены | `ai_usage_card.dart`  • `token_provider.dart` | есть |
| QR профиля | `my_qr_code_sheet.dart` | есть |
| Таб «Медиа» | `profile_shared_media_tab_view.dart` | есть, переиспользовать |
| Таб «Посты» | нужен WS-метод `get_user_posts` | **бэкенд-зависимость** |

Про посты честно: в `niosgram_provider.dart` есть только `get_feed` (общая лента, страницами по 20). Запроса «посты автора» нет. Follow-граф при этом существует (`follow_user` / `unfollow_user`, `isFollowing` на посте), но счётчиков подписчиков в состоянии нет.

**Никаких выдуманных счётчиков.** Строку статистики (посты / подписчики / дата регистрации) добавлять только после того, как бэкенд начнёт их отдавать. До этого таб «Посты» работает во временном режиме: фильтрует уже загруженную ленту по `author.username == me` и честно подписывает, что показаны посты из кэша ленты, либо показывает пустое состояние с кнопкой «Создать пост».

Важные детали каркаса:

- `SliverAppBar.large` сам даёт scrolled-under тональную подложку — но только если в теме убрать `appBarTheme.backgroundColor: Colors.transparent` (см. дизайн-аудит, там это отдельная находка).
- Каждый таб обязан быть самостоятельно скроллящимся (`ListView` / `CustomScrollView`). Никаких `shrinkWrap: true` — правило 7 моторного протокола.
- Нижний паддинг считается от `viewPaddingOf(context).bottom` плюс высота плавающего навбара — сейчас секция «Nios ID» обрезается именно из-за его отсутствия.

## 7. Код: быстрые действия (M3E button group)

Cвязанная группа кнопок — канонический компонент M3 Expressive: общая капсула снаружи, маленькие радиусы внутри, при нажатии сегмент «раздувается» до полной капсулы. Во Flutter готового виджета нет, поэтому собираем руками, но строго на `M3SpringCurves`.

```dart
class ProfileQuickAction {
  const ProfileQuickAction({
    required this.icon,
    required this.label,
    required this.onTap,
  });

  final IconData icon;
  final String label;
  final VoidCallback onTap;
}

class ProfileQuickActions extends StatelessWidget {
  const ProfileQuickActions({required this.actions, super.key});

  final List<ProfileQuickAction> actions;

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.symmetric(horizontal: 16, vertical: 8),
      child: Row(
        children: <Widget>[
          for (int i = 0; i < actions.length; i++) ...<Widget>[
            Expanded(
              child: _QuickActionSegment(
                action: actions[i],
                isFirst: i == 0,
                isLast: i == actions.length - 1,
              ),
            ),
            if (i != actions.length - 1) const SizedBox(width: 2),
          ],
        ],
      ),
    );
  }
}

class _QuickActionSegment extends StatefulWidget {
  const _QuickActionSegment({
    required this.action,
    required this.isFirst,
    required this.isLast,
  });

  final ProfileQuickAction action;
  final bool isFirst;
  final bool isLast;

  @override
  State<_QuickActionSegment> createState() => _QuickActionSegmentState();
}

class _QuickActionSegmentState extends State<_QuickActionSegment> {
  bool _pressed = false;

  @override
  Widget build(BuildContext context) {
    final ColorScheme scheme = Theme.of(context).colorScheme;
    final TextTheme textTheme = Theme.of(context).textTheme;

    const Radius inner = Radius.circular(8);
    const Radius outer = Radius.circular(28);
    final Radius active = _pressed ? outer : inner;

    return AnimatedContainer(
      duration: M3Durations.short4,
      curve: M3SpringCurves.spatial,
      height: 56,
      decoration: BoxDecoration(
        color: _pressed ? scheme.secondaryContainer : scheme.surfaceContainerHigh,
        borderRadius: BorderRadius.only(
          topLeft: widget.isFirst ? outer : active,
          bottomLeft: widget.isFirst ? outer : active,
          topRight: widget.isLast ? outer : active,
          bottomRight: widget.isLast ? outer : active,
        ),
      ),
      clipBehavior: Clip.antiAlias,
      child: InkWell(
        onTap: () {
          HapticService.tap();
          widget.action.onTap();
        },
        onHighlightChanged: (bool value) => setState(() => _pressed = value),
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: <Widget>[
            Icon(widget.action.icon, size: 20, color: scheme.onSurfaceVariant),
            const SizedBox(height: 2),
            Text(
              widget.action.label,
              maxLines: 1,
              overflow: TextOverflow.ellipsis,
              style: textTheme.labelMedium?.copyWith(color: scheme.onSurface),
            ),
          ],
        ),
      ),
    );
  }
}
```

## 8. Код: таб «Мои посты»

Провайдер с честным фолбэком, пока бэкенд не отдаёт посты автора:

```dart
class MyPostsState {
  const MyPostsState({
    this.posts = const <NgPost>[],
    this.hasMore = true,
    this.page = 1,
    this.isLoadingMore = false,
    this.isFallback = false,
  });

  final List<NgPost> posts;
  final bool hasMore;
  final int page;
  final bool isLoadingMore;
  final bool isFallback;

  MyPostsState copyWith({
    List<NgPost>? posts,
    bool? hasMore,
    int? page,
    bool? isLoadingMore,
    bool? isFallback,
  }) =>
      MyPostsState(
        posts: posts ?? this.posts,
        hasMore: hasMore ?? this.hasMore,
        page: page ?? this.page,
        isLoadingMore: isLoadingMore ?? this.isLoadingMore,
        isFallback: isFallback ?? this.isFallback,
      );
}

class MyPostsNotifier extends AsyncNotifier<MyPostsState> {
  String get _me => ref.read(authProvider).session?.username ?? '';

  @override
  Future<MyPostsState> build() async {
    try {
      final List<NgPost> first = await _fetchPage(1);
      return MyPostsState(posts: first, page: 1, hasMore: first.length >= 20);
    } catch (_) {
      return MyPostsState(posts: _fromFeedCache(), hasMore: false, isFallback: true);
    }
  }

  Future<List<NgPost>> _fetchPage(int page) async {
    final dynamic response = await ref.read(webSocketClientProvider).request(
      'get_user_posts',
      payload: <String, dynamic>{'username': _me, 'page': page},
    );
    if (response is Map && response['error'] != null) {
      throw Exception(response['error'].toString());
    }
    final dynamic posts = response is Map ? response['posts'] : response;
    if (posts is! List) return <NgPost>[];
    return posts
        .whereType<Map>()
        .map((Map item) => NgPost.fromJson(
              item.map((dynamic k, dynamic v) => MapEntry(k.toString(), v)),
            ))
        .toList(growable: false);
  }

  List<NgPost> _fromFeedCache() {
    final NiosgramState? feed = ref.read(niosgramProvider).value;
    if (feed == null || _me.isEmpty) return const <NgPost>[];
    return feed.posts
        .where((NgPost p) => p.author.username == _me)
        .toList(growable: false);
  }
}

final AsyncNotifierProvider<MyPostsNotifier, MyPostsState> myPostsProvider =
    AsyncNotifierProvider<MyPostsNotifier, MyPostsState>(MyPostsNotifier.new);
```

В UI: если `isFallback == true`, над списком показывается неброский `SettingsInfoTile`-подобный баннер с текстом «показаны только посты из загруженной ленты» — чтобы пустой список не выглядел как «у тебя нет постов». Пустое состояние — `EmptyStateWidget` + кнопка «Создать пост» на `/niosgram/create`.

**Бэкенд-зависимость:** нужен обработчик `get_user_posts` с пагинацией по 20 и полями, идентичными `get_feed`. `server_core/` из скоупа клиентских задач исключён, так что фазу 6 делать за фича-флагом и не блокировать ею остальное.

## 9. Nios ID: убрать раздел, перестать выбрасывать в браузер

1. С профиля секция «Nios ID» удаляется целиком. Управление остаётся там, где уже реализовано — Настройки → Аккаунт.
2. Если вход с профиля всё же нужен, это маленькая текстовая кнопка внутри карточки личности: `Управление Nios ID` + `Icons.open_in_new_rounded`, **без шеврона**.
3. Сам переход — не внешний браузер, а in-app вкладка с тональной шапкой приложения:

```dart
Future<void> openNiosIdWeb(BuildContext context, String path) async {
  final ColorScheme scheme = Theme.of(context).colorScheme;
  final Uri uri = Uri.parse('https://ni-os.ru$path');
  try {
    await launchUrl(
      uri,
      mode: LaunchMode.inAppBrowserView,
      browserConfiguration: BrowserConfiguration(showTitle: true),
      webViewConfiguration: const WebViewConfiguration(enableJavaScript: true),
    );
  } catch (e) {
    if (context.mounted) AppToast.showError(context, e);
  }
}
```

`LaunchMode.inAppBrowserView` на Android поднимает Custom Tabs: сессия и куки сохраняются, шапка окрашивается, кнопка закрытия возвращает точно туда, откуда ушёл. Ощущение «меня выкинуло из приложения» исчезает. Если нужен полный контроль над цветом шапки — `flutter_custom_tabs` с `CustomTabsOptions(colorSchemes: ...)` от `scheme.surfaceContainer`.
4. Сократить поводы уходить в веб: `two_fa_screen.dart` (12 460 B) уже написан, но роуты `/2fa` застабены редиректом на `/login`. После его оживления в вебе останутся только смена почты/пароля и удаление аккаунта.

## 11. M3E-детали, которые дадут «дорогой» вид

1. **Шейп-морф аватара.** `flutter_m3shapes` уже в зависимостях и почти не используется. Свой аватар на профиле — идеальное место: маска морфится из круга в `c9SidedCookie` при нажатии, на `M3SpringCurves.bouncy` и `M3Durations.short4`. Это ровно тот приём, которым M3E отличается от базового M3.
2. **Волнистый прогресс у AI-токенов.** После `useMaterial3` с `year2023: false` стандартный `LinearProgressIndicator` получает волнистый трек и стоп-индикатор. Сейчас на 100% это просто сплошная тёмная плашка во всю ширину — самый тёмный объект экрана при нулевой информативности.
3. **Крупное имя.** На экране «про меня» имя должно быть `headlineLarge`, а не `titleMedium` с `w800`, как в `ProfileHeaderDelegate`. После правки типошкалы (см. дизайн-аудит) — `headlineLargeEmphasized`.
4. **Тональные поверхности вместо белого.** Карточка личности — `surfaceContainerLow`, вложенные блоки — `surfaceContainerHigh`. Ни одного `Colors.white`, ни одной тени.
5. **Единая геометрия.** Карточки — `AppRadii.lg`, чипы и сегменты — капсулы, иконочные контейнеры — `AppRadii.sm`. Никаких локальных `circular(12)` / `circular(24)`.
6. **Доступность.** Все интерактивные элементы ≥ 48 dp: сегменты группы 56, строки табов 56, чипы с `MaterialTapTargetSize.padded`.

## 13. Критерии приёмки

1. На профиле ровно **один** вход в настройки и **один** вход в редактирование.
2. Раздела «Nios ID» нет; Nios ID присутствует как копируемый чип.
3. Ни одна ссылка не открывается во внешнем браузере; веб открывается в in-app вкладке.
4. Экран заполнен: даже с пустым био и без постов видны хедер, карточка личности, группа действий, табы, график работы и AI-токены — пустоты ниже фолда нет.
5. Последний блок не обрезается навбаром при скролле до конца.
6. В свёрнутом хедере виден `@ник`, а не символ `@`.
7. Ни одного `Colors.white`, `withOpacity`, `boxShadow` в файлах профиля.
8. Табы переключаются без рывков; при переключении не пересоздаются состояния соседних табов.
9. Цвета бейджей прогнаны через `Blend.harmonize` — на розовой схеме нет неоновой мадженты и неонового зелёного.
10. `flutter analyze` — ноль ошибок и предупреждений; `dart test` проходит.
11. Ни одного выдуманного счётчика: статистика показывается только если бэкенд её отдал.

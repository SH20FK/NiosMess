# 06. Настройки на десктопе и в вебе — аудит позиции «полноценный десктопный интерфейс»

Роль: сторонник десктопа и веба. Задача отчёта — доказать (или опровергнуть) тезис: **на широком экране настройки NiosMess должны быть настольным интерфейсом с постоянной навигацией, а не растянутым телефоном.** Дата: 2026-11-22. Код: `F:/Niosmess V2/pulse_flutter`.

Метод: только чтение кода и тестов; `flutter`/`dart`/`git` не запускались. Все утверждения о нашем коде — со ссылкой `путь:строка`. Утверждения о чужих продуктах — со ссылкой на источник. Всё, что не проверено запуском, помечено в разделе «Не проверено».

## 1. Десять главных выводов

1. **Архитектура правильная, но порог включения двух панелей сломан.** Двухпанельный режим уже существует (`lib/screens/profile_screen.dart:603-674`), но включается по *внутренней* ширине ≥ 840 (`profile_screen.dart:785-787`), а внутри окна уже стоит рельс 96 dp (`lib/screens/main_shell_screen.dart:492-496`, `lib/widgets/nav/app_nav_item.dart:21`). Итог: на Windows две панели появляются только при окне ≈ 937 dp, а в диапазоне **840–936 dp пользователь видит рельс и одновременно «телефонные» настройки в одну колонку**. Это и есть «растянутый телефон».
2. **Веб и Windows ведут себя по-разному на одной и той же ширине.** В вебе первое условие порога — 720 (`profile_screen.dart:786`), поэтому с 840 dp веб показывает две панели, а Windows — нет. Один и тот же продукт на одной ширине выглядит двумя разными приложениями.
3. **Правая панель при включении сплита всего 500 dp** (`width 840 − master 340`), то есть уже телефона. Сплит включается тогда, когда деталь ещё нечитаема, и не выключается, когда она становится слишком широкой (на 2560 dp правая панель 2124 dp, контент внутри всё равно 860 — `lib/widgets/settings/settings_shell.dart:36,166-173`).
4. **Подэкраны выбивают из сплита.** «Правило конфиденциальности», «Заблокированные», обои пушатся полноэкранным маршрутом (`lib/screens/settings_privacy_screen.dart:22-28`, `lib/router/app_router.dart:607-619`), хотя соседние переходы между разделами корректно живут внутри панели (`lib/widgets/settings/account_security_section.dart:110-120`, `settings_privacy_screen.dart:293-303`). На 1920 dp открытие одного правила заменяет всё окно страницей с 140-пиксельной шапкой.
5. **Клавиатуры нет.** В настройках нет ни одного `Shortcuts`/`CallbackShortcuts`: Escape не закрывает настройки и не возвращает к списку (в чатах Escape есть — `lib/screens/chat_list_screen.dart:569-580`, `lib/screens/chat_detail_screen.dart:2378-2382`). Нет `Ctrl+,` (открыть настройки), нет `Ctrl+F` (к поиску), нет стрелок по списку разделов. `Ctrl+K` в списке чатов есть (`chat_list_screen.dart:577-579`) — то есть стандарт внутри продукта уже принят, просто не доведён до настроек.
6. **Мышь поддержана наполовину.** Курсор-рука, фокусная рамка 2 dp и активация Enter/Space есть (`lib/widgets/settings/pressable_surface.dart:99-131`), но **hover-состояния у строк нет вообще** — это `AnimatedContainer` + `GestureDetector`, без InkWell/MouseRegion (`pressable_surface.dart:87-141`). В настольном списке разделов из 11 строк отсутствие hover читается как «некликабельно».
7. **Скроллбары отключены на Windows.** `AppScrollBehavior.buildScrollbar` возвращает ребёнка без обёртки для всего, что не веб (`lib/main.dart:490-508`), а для веба — только если у ScrollView есть собственный контроллер. У левой панели контроллера нет (`profile_screen.dart:633-635`) → на Windows в настройках нет индикатора прокрутки, хотя список гарантированно прокручивается (оценка высоты — §4.3).
8. **Левая панель — это хаб-страница, а не навигация.** В ней заголовок «Настройки» (`profile_screen.dart:636-645`), карточка профиля с аватаром 84 dp (`profile_screen.dart:459-526`), поиск, карточки проблем, четыре группы карточек и «Выйти» (`profile_screen.dart:646-661`). Discord/macOS/Windows держат в колонке навигации только: поиск + плотный список + одну строку аккаунта.
9. **Веб-часть сделана аккуратно, но не как веб.** Адрес меняется на каждый раздел (`profile_screen.dart:69-77`), легаси-ссылки редиректятся (`lib/router/web_settings_location.dart:2-24`, `app_router.dart:540-674`), «назад/вперёд» браузера работают, потому что Flutter Router кладёт новую запись истории на каждое изменение URI (`F:/Flutter/flutter/packages/flutter/lib/src/widgets/router.dart:1522-1533`). Но канонический URL — `/main/settings?section=x` (`app_router.dart:529-536`), а не `/settings/x`; фрагмент при редиректе теряется (`web_settings_location.dart:20-23`); строки разделов — не ссылки, «открыть в новой вкладке» невозможно.
10. **Мёртвый код выдаёт незавершённость десктопной ветки.** `SettingsResponsiveShell` не используется нигде (`lib/features/settings/presentation/settings_responsive_shell.dart:14-15` — единственное упоминание), `SettingsScaffold` в `lib` не используется тоже (`lib/widgets/settings_ui.dart:16`), но именно его проверяет «десктопный» тест (`test/widgets/settings_desktop_restructure_test.dart:41,110`). Тест зелёный, а реальный шелл он не покрывает.

## 2. Эталоны: как это делают на десктопе

| Продукт | Форма | Левая колонка | Ширина контента | Закрытие / назад | Сохранение | Клавиатура |
|---|---|---|---|---|---|---|
| **Discord** | полноэкранный слой поверх всего приложения (не отдельное окно) | плоский список разделов, свой скролл | узкая фиксированная колонка по центру (наблюдение, не проверено) | `Esc` закрывает; `Alt+←` — назад | мгновенно, кроме профиля («Save Changes») | `Ctrl+,` — открыть настройки, `Ctrl+/` — список шорткатов, `Alt+←` — назад ([Discord Commands, Shortcuts, and Navigation Guide](https://support.discord.com/hc/en-us/articles/31232432266647-Discord-Commands-Shortcuts-and-Navigation-Guide)) |
| **Slack** | отдельный диалог/окно «Preferences» | список категорий | одна колонка | закрытие диалога | мгновенно (правки применяются без «Сохранить») ([Slack: Configure your Slack notifications](https://slack.com/help/articles/201355156-Configure-your-Slack-notifications)) | `Ctrl+,` — Preferences, `F6`/`Shift+F6` — переход между зонами ([Slack keyboard shortcuts](https://slack.com/help/articles/201374536-Slack-keyboard-shortcuts)) |
| **Telegram Desktop** | страница внутри главного окна, заменяет область чата | список разделов + «назад» | одна колонка | `Esc` — Go back / Exit ([Keyboard shortcuts for Telegram Desktop](https://usethekeyboard.com/telegram)) | мгновенно | `Esc`, `Ctrl+Tab` по чатам, `Ctrl+F` поиск ([там же](https://usethekeyboard.com/telegram)) |
| **Windows 11 Settings** | отдельное окно приложения | панель навигации: иконка + подпись, 11 категорий ([Exploring Windows Settings](https://support.microsoft.com/en-us/windows/experience/exploring-windows-settings)) | страница категории с карточками | системный заголовок окна, «назад» и хлебные крошки внутри страницы ([таймкод-конспект](https://www.youtube.com/watch?v=QM-k8cYpAyg)) | «большинство настроек применяется сразу» ([там же](https://www.youtube.com/watch?v=QM-k8cYpAyg)) | `Ctrl+E` — фокус в поиск, `Win+I` — открыть ([Understand and explore Windows Settings](https://support.microsoft.com/en-us/accessibility/windows/understand-and-explore-windows-settings)) |
| **macOS System Settings** | отдельное окно | сайдбар: список + поле поиска сверху | одна колонка по центру | системное закрытие окна | мгновенно, без «Сохранить» | поиск в сайдбаре, результаты появляются там же ([System Settings on your Mac](https://support.apple.com/guide/mac-pro/system-settings-apda966cb8af/mac)) |
| **Linear** | отдельная страница приложения (не модалка) | сайдбар разделов | узкая колонка | `Esc` — на уровень назад ([Linear shortcuts](https://www.pie-menu.com/shortcuts/linear)) | мгновенно | `Cmd/Ctrl+K` командная палитра, `G S` — settings, `Esc` назад ([там же](https://www.pie-menu.com/shortcuts/linear)) |

Что из этого — устойчивый десктопный консенсус (и что нам стоит взять):

- **Постоянная левая навигация + одна колонка контента с ограничением ширины.** Никто не растягивает формы на 2000 px и никто не прячет разделы в «ещё».
- **Escape — универсальный «назад/закрыть»**. Это самая частая клавиша в настройках на всех пяти эталонах.
- **Поиск живёт в левой колонке** (macOS, Windows) и открывается горячей клавишей (`Ctrl+E`, `Ctrl+K`), а не только кликом.
- **Применение мгновенное**, кнопка «Сохранить» — исключение (только профиль у Discord).
- **Хлебные крошки или явный заголовок раздела** в правой части (Windows), иначе при постоянной навигации пользователь теряет место в иерархии.
- **Настройки — не отдельное приложение**: Windows/macOS открывают их в своём окне, Discord/Telegram — внутри основного. Для мессенджера «страница внутри окна + мастер-деталь» (наш текущий выбор) — правильный; вопрос только в качестве исполнения.

## 3. Как устроено у нас: карта поведения

### 3.1 Где живут настройки
- Роут `/main/settings` → `MainShellScreen(tab: 'settings')` → четвёртая страница `ProfileScreen` (`lib/screens/main_shell_screen.dart:513-611`). `SettingsHubScreen` — тонкая обёртка (`lib/screens/settings/settings_hub_screen.dart:8-16`).
- Рельс приложения: 96 dp, включается от 840 dp по ширине окна, на всех платформах (`main_shell_screen.dart:489-496,672-681`, `lib/widgets/nav/app_nav_item.dart:21`).
- Маршруты разделов `/settings/*` существуют всегда (`lib/router/app_router.dart:537-674`); в вебе большинство из них редиректится в `/main/settings?section=…` (`app_router.dart:540-674`).

### 3.2 Порог двух панелей
```dart
// lib/screens/profile_screen.dart:784-787
final browser = ref.watch(clientCapabilitiesProvider).browserWorkspace;
final bool isWide =
    width >= (browser ? 720 : Breakpoints.medium) &&      // width = LayoutBuilder (уже минус рельс)
    MediaQuery.sizeOf(context).width >= Breakpoints.medium;
```
- `Breakpoints.medium = 840` (`lib/core/theme/expressive_tokens.dart:190`).
- Внутри `MainShellScreen` контент уже ужат на `railWidth + 1 = 97` (`main_shell_screen.dart:492-496`), поэтому для Windows фактический порог — **окно ≈ 937 dp**; для веба — **840 dp** (первое условие 720 выполняется легче).
- Высота не проверяется вообще, хотя в проекте есть `Breakpoints.twoPaneMinHeight = 480` и `Breakpoints.twoPane(size)` (`expressive_tokens.dart:198-206`), которые `MainShellScreen` использует для чатов (`main_shell_screen.dart:493`). То есть **правило «две панели только если хватает высоты» для настроек не применяется**: окно 1200×400 получит две панели с обрезанными списками.

### 3.3 Что в панелях
Левая (`profile_screen.dart:620-664`): ширина 340 (в вебе `width*0.27` с клампом 300–360, строка 622-624), фон `surface`, правая граница `outlineVariant α .35`; содержимое — заголовок «Настройки» (636-645), карточка профиля (646-652), `SearchAnchor` (653), до двух карточек проблем (655), четыре группы карточек по `SettingsRegistry.getTopLevelSections()` (656-660), «Выйти» (661).
Правая (`profile_screen.dart:665-670`): `Expanded` + `_animatedDetail(selected)`, то есть один из 13 экранов с `isEmbedded: true` (`profile_screen.dart:676-706`).

Разделов в левом списке **11**: account, appearance, chats, notifications→preferences, privacy, storage, language, system_device, energy_saving, plus, about (`lib/services/settings/settings_registry.dart:40-320`). **Сессии и E2EE в списке отсутствуют** — в них можно попасть только из деталей (`account_security_section.dart:104-121`, `settings_privacy_screen.dart:288-303`).

### 3.4 Что происходит при сужении окна
- **Нативный десктоп (Windows/macOS/Linux)**: деталь была выбрана в панели, маршрут не пушился (`profile_screen.dart:424-429` → `_selectSection`). При сужении ниже порога `build` уходит в `_buildMobileProfile` (`profile_screen.dart:827-836`) — пользователь видит хаб-список, подэкран исчезает. Выбор остаётся в провайдере и вернётся при расширении, но визуально это «выброс на главную».
- **Веб**: если в URL есть `section` и ширина < порога — отдельная страница с `AppBar`, заголовком раздела и «назад» (`profile_screen.dart:788-813`), кнопка ведёт на `/main/settings` (`profile_screen.dart:799`). Это поведение зафиксировано тестом (`test/widgets/web_settings_paste_test.dart:127-143`).
- **Открытый pushed-подэкран** (`/settings/privacy/rule/x`) не зависит от ширины: он остаётся полноэкранной страницей при любом размере окна.
- Обратный переход «телефон → десктоп» не согласован: открытая push-страница `/settings/account` при расширении остаётся поверх шелла отдельной страницей, а не превращается в правую панель.

### 3.5 Сохраняется ли выбор
- В памяти: да, `desktopSelectedSettingsSectionProvider` (`lib/providers/settings_navigation_provider.dart:29-40`).
- Между запусками: **нет** — `build() => SettingsSectionId.account` (строка 31), никакой персистентности. Windows/macOS возвращают последнюю открытую страницу (по памяти — поведение системы; в нашем коде не реализовано).
- В вебе: да, через `?section=` в URL (`profile_screen.dart:69-77`).
- Прокрутка левой панели: сохраняется `PageStorageKey('settings-navigation-scroll')` (`profile_screen.dart:634`).

### 3.6 Пустое состояние правой панели
**Отсутствует.** По умолчанию всегда выбран `account` (`settings_navigation_provider.dart:31`), поэтому «Настройки» на широком экране сразу открывают «Аккаунт». Это приемлемо (Windows 11 тоже открывает «Система»), но означает, что «хаб» как отдельное состояние на десктопе не существует: вернуться к обзору нельзя, кроме клика по другому разделу.

### 3.7 Ограничение ширины контента
- `SettingsShell.maxWidth = 860` (`lib/widgets/settings/settings_shell.dart:36`), `Align(topCenter) + ConstrainedBox` (166-173, 176-185).
- `padding` по 28 dp при ширине ≥ 840 (`settings_shell.dart:60-64`).
- Второй, неиспользуемый шелл — те же 860 (`settings_responsive_shell.dart:96`).
- На окне 2560: правой панели 2124 dp, контента 860 → по ~630 dp пустоты с каждой стороны; макет остаётся одноколоночным на любой ширине. `Breakpoints.expanded = 1200` и `large = 1600` (`expressive_tokens.dart:193-196`) в настройках не используются нигде (проверено grep по `lib`).

### 3.8 Веб: адрес, ссылки, история
- Клик по разделу: `context.go('/main/settings?section=${section.name}')` (`profile_screen.dart:70-72`) — адрес меняется.
- Прямая ссылка: `/settings/appearance` → `webSettingsRedirect` → `/main/settings?section=appearance` (`app_router.dart:555-563`, `web_settings_location.dart:2-24`). Работает и для подразделов: `?section=e2ee`, `?section=sessions` (`app_router.dart:651-674`).
- `/settings/system-device` в вебе принудительно ведёт на `about` (`app_router.dart:640-644`), и `setSelectedSection` тоже подменяет systemDevice → about на вебе (`settings_navigation_provider.dart:34-37`). Раздел «Система и устройство» на вебе не существует — это осознанно.
- «Назад/вперёд» браузера: Flutter Router создаёт новую запись истории на каждое изменение URI (`F:/Flutter/flutter/packages/flutter/lib/src/widgets/router.dart:1522-1533`; `C:/pubcache/hosted/pub.dev/go_router-17.5.0/lib/src/information_provider.dart:109-136`). Значит шаги по разделам должны откатываться по одной. Вживую не проверял — см. §6.
- Чего нет:
  - канонический путь раздела — query-параметр, а не путь: `/main/settings?section=appearance` (ссылки некрасивые, хлебные крошки из пути не собрать);
  - фрагмент (`#anchor`) при редиректе отбрасывается — `Uri(path:, queryParameters:)` без `fragment`, хотя комментарий файла обещает «including search anchors» (`web_settings_location.dart:1,20-23`);
  - подстраницы `/settings/privacy/rule/:key`, `/settings/privacy/blocked-users`, `/settings/wallpaper` редиректа не имеют (`app_router.dart:607-619,571-582`) и в вебе открываются вне рабочей области — без рельса и без общего хрома;
  - строки разделов реализованы `GestureDetector` (`pressable_surface.dart:132-140`), а не ссылками: `Ctrl+Click`, средняя кнопка, «открыть в новой вкладке», копирование адреса раздела не работают;
  - `Ctrl+F` не перехватывается — в вебе откроется поиск браузера по канвасу (пустой).

### 3.10 Переходы между разделами
`_animatedDetail` (`profile_screen.dart:571-601`): `AnimatedSwitcher` (medium1 / short3, `expressiveDecel`/`expressiveAccel`) + fade и сдвиг **0.015 по вертикали**, `layoutBuilder` держит исходящий кадр в `Stack` с `ExcludeFocus`+`IgnorePointer`. Левая панель не участвует — **едет только правая панель, вся страница не смещается. Это сделано правильно.**
Замечания: (1) вертикальный сдвиг 1.5% при смене раздела читается как «подпрыгивание», у эталонов переключение панели — чистый fade или кроссфейд без сдвига; (2) подсветка выбранной строки меняется мгновенно, без анимации (`settings_list_item.dart:311`), поэтому связка «клик → подсветка → контент» рвётся по времени; (3) исходящий кадр остаётся в `Stack` до конца анимации и продолжает лейаутиться — на медленных машинах это лишняя работа, но не баг.

### 3.11 Windows
- Заголовок окна: жёстко `'NiosMess'` (`lib/core/services/desktop_window_service.dart:40`), не меняется от раздела. `titleBarStyle: normal` — нативный заголовок, кастомного хрома нет (строка 39).
- Минимальный размер окна: **680×520** (`desktop_window_service.dart:37`), то есть **ниже собственного порога сплита**: в минимальном окне настройки всегда одноколоночные.
- `WM_GETMINMAXINFO`/`SetMinimumSize` в нативном раннере не реализованы (`windows/runner/win32_window.cpp` — нет таких обработчиков), ограничение живёт в `window_manager`.
- Первый кадр: окно 1100×750, по центру (`windows/runner/main.cpp:34-38`) — то есть на старте уже «десктопная» ширина, но при 1100 настройки получают сплит только потому, что 1100−97=1003 ≥ 840. На 1000×700 — уже нет.
- В диапазоне 840–1000 dp: рельс есть, две панели нет, контент центрируется в 860 с `AppBar.large` 140 dp и отступами 16 — визуально это планшет, а не настольное приложение.

## 4. Измерения и оценки

### 4.1 Геометрия текущего сплита

|---|---|---|---|---|---|

Ширины взяты из `main_shell_screen.dart:492-496`, `app_nav_item.dart:21`, `profile_screen.dart:620-624,785-787`, `settings_shell.dart:36,60-64`.

### 4.2 Правка правила
Порог должен считаться **от минимума правой панели**, а не от магической константы: `threshold = railWidth + masterMin + detailMin = 96 + 320 + 560 ≈ 976`. Иначе сплит либо включается слишком рано (сейчас: detail 500), либо слишком поздно (Windows 937).

### 4.3 Оценка высоты левого списка (оценка, не измерение)
Заголовок «Настройки» ~28 + карточка профиля ~236 (padding 20+20, аватар 84, имя 28, @username 20, кнопки 48 — `profile_screen.dart:465-526`) + поиск 56 + отступ 20 + 4 заголовка групп ~28 каждый + 11 строк по 64–68 (`settings_list_item.dart:230-233`) + «Выйти» 64 + padding 40 ≈ **1210 dp**. При окне 750 dp список прокручивается на ~460 dp; при минимальных 520 dp — на ~700 dp. Пользователь не видит «Плюс» и «О приложении», пока не проскроллит — при том, что это постоянная навигация, а не лента.

## 6. Целевой макет для трёх ширин

Принцип: пороги выводятся из минимумов панелей, а не из одной константы. Рельс приложения — 96 dp (существующий, `app_nav_item.dart:21`).

### A. `< 600 dp` — телефон, один столбец (как сейчас, без изменений)
- Контент: ширина = экран, padding 16 (`settings_shell.dart:61-64`).
- Хаб (`profile_screen.dart:528-569`): шапка профиля, поиск 56, группы карточек, строки 64.
- Раздел → push; `SliverAppBar.large` 140 (`settings_shell.dart:84-119`); «назад» — стрелка/Escape (Escape добавить).
- Никаких скроллбаров и hover (там их и не должно быть).

### B. `600–839 dp` — планшет, один столбец с ограничением
- Контент `maxWidth = 720`, padding 24, строки 56–64.
- Шапка раздела в деталях: **56 dp** вместо 140 (крошки `Настройки / Оформление` + «назад»), поиск — вторым рядом 48 dp.
- Хаб: те же группы, но карточки могут идти в 2 колонки при ≥ 720 (2×340 + 24).
- Две панели **не включать**: правая была бы < 500.
- Рельс приложения здесь ещё не показывается (порог 840, `main_shell_screen.dart:492`).

### C. `≥ 840 dp` — две панели (порог фактически ≈ 976 с рельсом)
- **Левая колонка навигации: 320 dp** (min 300, max 340), своя прокрутка, `surface` + волосяная граница `outlineVariant α .35`.
  - Sticky-поиск 48 dp (`surfaceContainerHigh`), `Ctrl+F` → фокус.
  - Группы разделов: подпись 12 sp `onSurfaceVariant`, строки **40–44 dp**, радиус 10–12, hover `surfaceContainerHighest`, выбранная — `secondaryContainer`, без шеврона.
  - Внизу — одна строка аккаунта 56 dp (аватар 32, имя, шеврон) → «Аккаунт»; «Выйти» — внутри раздела «Аккаунт».
  - Проблемы конфигурации — точка/бейдж на строке, не карточки.
- **Правая панель: `min 560`**, заголовок раздела 24–28 + крошки 20 (72 dp сверху), горизонтальный padding 32.
  - Контент `maxWidth = 880` по центру.
  - Подразделы (правило приватности, заблокированные, обои, сессии) — **внутри панели**: локальный стек + крошки, левая колонка остаётся.
- **Порог:** `rail 96 + master 320 + detail 560 = 976`; округлить до **960** и применять на Windows/вебе одинаково (при 960 detail = 960−96−320 = 544, что ниже 560 → берём 976, либо master 300 → 956). Рекомендую: **сплит от 960 dp при master 300** (detail 564).
- Escape: подэкран → назад внутри панели; на верхнем уровне → вкладка «Чаты».
- Заголовок окна: `Настройки · <раздел> — NiosMess`.

### D. Бонус: `≥ 1200 dp` (`Breakpoints.expanded`, сейчас мёртв)
- Контент правой панели **1120**, карточки в 2 колонки (2×440 + 24 gap) для «Оформления», «Чатов», «Приватности».
- `≥ 1600 dp` (`Breakpoints.large`): третья колонка подраздела 320 dp либо боковая панель предпросмотра (для «Оформления» — превью темы, для «Обоев» — превью чата).

### E. Сквозные правила для всех трёх ширин
1. `Ctrl+,` — открыть настройки; `Esc` — назад/закрыть; `Ctrl+F` — поиск.
2. ↑/↓ + Home/End + Enter в левой колонке; Tab-порядок начинается с поиска, не с аватара.
3. Hover на всех кликабельных строках; скроллбары 6–8 dp на десктопе и вебе.
4. Правая кнопка на строке раздела: «Открыть», «Скопировать ссылку» (веб).
5. Один и тот же вид строки (40–44 dp) во всех ширинах — меняется только плотность отступов.

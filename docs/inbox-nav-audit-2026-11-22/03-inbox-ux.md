## 4. Трение и баги, доказуемые из кода

### 4.1 Готовый экран «Контакты + Звонки» недостижим

`lib/screens/contacts_screen.dart` — 1400+ строк: табы «Контакты/Звонки»
(`:370-410`), поиск по людям/чатам/сообщениям (`:1046, 1064-1138`), избранные
(`:676-770`), история звонков (`:445-455`). Ни один файл его не импортирует, а
маршруты ведут в никуда:

- `/contacts` → `redirect('/main/chats')` (`app_router.dart:241`)
- `/main/contacts` → `redirect('/contacts')` (`app_router.dart:242-245`)

Следствие: **истории звонков в приложении нет вообще** — единственное вхождение
`CallLogView` в lib — внутри мёртвого экрана (`contacts_screen.dart:28, 453`).
Комментарий в шелле до сих пор считает контакты табом: `main_shell_screen.dart:400`.

### 4.2 Повторный тап по активному табу — звук без действия

`app_bottom_nav.dart:40-46` играет тик и хаптик (хаптик — только при смене, звук —
всегда), затем `_onTapTab`, который при совпадении таба выходит: `main_shell_screen.dart:359-361`.
Пользователь слышит отклик и не получает результата — это читается как «баг», а не
как «тут нечего делать».

### 4.3 Два PopScope на одном маршруте: «назад» в двухпанельном режиме делает два дела

`ChatDetailScreen` в split-режиме — не маршрут, а виджет внутри `/main/:tab`
(`main_shell_screen.dart:525-539`), и он вешает свой `PopScope` с `canPop: false`
(`chat_detail_screen.dart:2436-2441`). Шелл вешает свой (`main_shell_screen.dart:394-417`).
Flutter опрашивает **все** `PopEntry` одного маршрута:

```dart
void onPopInvokedWithResult(bool didPop, T? result) {
  for (final PopEntry<Object?> popEntry in _popEntries) { ... }
}
```
(`F:\Flutter\flutter\packages\flutter\lib\src\widgets\routes.dart`, `ModalRoute`)

То есть одно нажатие «назад» на Android-планшете закрывает правую панель **и**
показывает тост «нажмите ещё раз, чтобы выйти», взводя выход из приложения. Проверить
на устройстве стоит обязательно, но по коду оба обработчика срабатывают.

### 4.4 Быстрый поиск: три чипа, из которых два не работают, третий ищет по слову «непрочитан»

`inbox_search_screen.dart:294-335`:

- «Группы» (`:317-323`) и «Каналы» (`:324-330`) меняют только `_scope`, но при
  пустом запросе тело всё равно рисует подсказки (`:195-196`, `:294`). Визуально —
  тап в пустоту.
- «Непрочитанные» (`:310-316`) подставляет текст `'непрочитан'` в поиск, а поиск
  ищет по имени/юзернейму/описанию (`:150-158`). Результат — «Ничего не найдено».

### 4.5 Смешанные языки: инбокс локализован, а всё, что за FAB и лупой, — нет

Инбокс берёт строки из l10n (`chat_list_screen.dart:272-273, 384-388`,
`chat_filter_bar.dart:84-141`), а соседние экраны — хардкод по-русски:

- поиск: `inbox_search_screen.dart:171-177` («Все», «Чаты», «Сообщения», «Люди»),
  `:243`, `:299`, `:312`, `:385-386`, `:396`, `:424`, `:461-464`, `:477`, `:484`
- пикер: `people_picker_screen.dart:87-90, 150, 211-212, 223-224, 237, 250-251, 287-288, 294, 301-302`
- группа: `create_group_members_screen.dart:66, 182, 185, 203, 216, 234-235, 291-292`;
  `create_group_details_screen.dart:112-113, 125, 141-142, 177, 182, 195-196, 211, 219, 277, 301`
- канал: `create_channel_screen.dart:118, 131, 151, 166, 169, 185, 220, 226, 238-239, 256-260, 288, 325`

При EN-локали это прямое нарушение правила AGENTS.md «All user-facing strings via
`context.l10n.key`» и выглядит как недоперевод.

### 4.6 Мёртвый код, который путает поддержку

- `M3SpeedDialFab` (`widgets/chat/m3_speed_dial_fab.dart`, 409 строк) используется

- `InboxSearchLauncher` (`features/chats/presentation/inbox_search_launcher.dart`)

### 4.7 Пустой инбокс нового пользователя — тупик

При `filter == all` и пустом списке показывается `chatListNoChats`
(`chat_list_screen.dart:380-398`), а это строка «Чаты не найдены.» /
«No chats found.» (`lib/l10n/app_localizations_ru.dart:1091`,
`app_localizations_en.dart:1088`) — текст из поиска, а не из онбординга. CTA нет
(`canResetFilters == false` → `actionLabel: null`, `:392-395`). Единственный путь —
догадаться, что карандаш в углу открывает меню.

### 4.8 Мелочи, которые чувствуются

- Фильтр типа не переживает запуск (`chat_filter_provider.dart:5-11`), а папка
  переживает (`chat_productivity_provider.dart:346-405`). Два соседних контрола с
  разной памятью.
- Выбранный фильтр и папка применяются одновременно (пересечение)
  (`chat_list_screen.dart:361-366`), при этом «Непрочитанные» подсвечивается
  независимо от папки (`chat_filter_bar.dart:92-98`) — состояние читается неверно.
- `/main` без чата на широком экране — заглушка «выберите чат», Esc и «назад» её не
  закрывают (в отличие от кнопки в шапке чата: `chat_detail_screen.dart:142-150`).
- Нет скроллбара и клавиатурного обхода списка на десктопе (см. §1.3).

## 5. Навигационная модель: три варианта

Сейчас: три таба — «Чаты», «NiosGram», «Настройки» (`main_shell_screen.dart:78`),
вход в настройки дублируется аватаром в шапке (`chat_list_header.dart:136-149`),
контакты и звонки недостижимы (§4.1), FAB — «меню из пяти пунктов»
(`compose_action_sheet.dart:14-39`).

**Вариант A. Оставить 3 таба, добавить точки входа в шапку.**
Чаты / NiosGram / Настройки. В шапке инбокса: лупа, иконка «Люди» (ведёт в готовый
`ContactsScreen`), аватар (настройки). FAB остаётся меню.
Плюсы: минимальная правка (один `IconButton` + маршрут), ничего не ломает привычку,
`ContactsScreen` уже готов. Минусы: в шапке 4 иконки на узком экране; звонки всё ещё
на два уровня глубже, чем у конкурентов; «Настройки» остаются табом, хотя это самая
редкая поверхность.

**Вариант B. Вернуть 4-й таб «Контакты» (с сегментом «Звонки»).**
Чаты / Контакты / NiosGram / Настройки. Аватар из шапки убрать (иначе два входа в
одно).
Плюсы: контакты и звонки на том же уровне, что у Telegram/WhatsApp/Signal; сегмент
уже реализован (`contacts_screen.dart:370-410`). Минусы: четыре таба при 80 dp высоты
(`app_bottom_nav.dart:91`) — тесно на 320 dp; NiosGram и Настройки становятся ещё
«дальше»; SPA-переходы в вебе потребуют правки rail (`main_shell_screen.dart:452, 627-633`).

**Вариант C. Два таба, остальное — шапка/рейл.**
Чаты / NiosGram; настройки — только аватар в шапке, контакты и звонки — иконки в
шапке (или сегмент в инбоксе). На широких экранах — навигационный рейл вместо
таб-бара.
Плюсы: снимает главную претензию «Настройки занимают целый таб ради редкого экрана»;
шапка становится честным центром навигации; на планшете экономит 80 dp по высоте.
Минусы: настройки перестают быть «одним тапом» (для тех, кто туда ходит часто);
на телефоне в шапке 4 иконки; ломает существующие ключи навигации и тесты, где
`/main/settings` — таб.

**Что должен делать FAB — три честных варианта:**
1. как сейчас — меню из 5 пунктов (гибко, но 2 тапа до «написать человеку», самое частое действие);
2. `extended` FAB «Написать» → сразу пикер людей, а группа/канал/секрет/ссылка —
   в долгом нажатии или в «＋» рядом (1 тап до главного сценария, риск: остальные
   действия станут незаметными);
3. FAB повторяет последнее использованное действие (Telegram-подобно), остальное — меню
   (быстро для «профи», но непредсказуемо для нового пользователя).

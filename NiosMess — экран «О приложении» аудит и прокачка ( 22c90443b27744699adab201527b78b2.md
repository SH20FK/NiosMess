# NiosMess — экран «О приложении»: аудит и прокачка (M3 Expressive)

## Что сейчас на экране

`pulse_flutter/lib/screens/settings_about_screen.dart` (~50 КБ, обёртка `SettingsShell`, поддержка `isEmbedded` для десктопного master-detail).

Структура: hero-карточка с логотипом и чипом версии → карточка «Обновление системы» (OTA) → `SegmentedButton` на 4 таба → контент таба в `AnimatedSwitcher` → футер с копирайтом.

Табы: Разработчики, Документы, FAQ (10 аккордеонов), История версий.

Визуально сделано аккуратно, но по сути экран сейчас показывает **неправду о версии**, дублирует логику обновления и на 70% не локализован. Ниже — разбор и план.

## 1. Экран врёт о версии и истории — это главное

### Три источника версии, два из них мёртвые

`core/constants/app_constants.dart` содержит с комментарием «matching pubspec.yaml»:

- `appVersion = '3.49.2'`
- `appBuildNumber = '103'`
- `appVersionWithPrefix = 'v3.49.2'`
- `appFullVersion = 'v3.49.2+103'`

А в `pubspec.yaml` сейчас `3.59.5+134` (после работ по плавности — `3.60.0+136`). Расхождение — **10 минорных версий и 31 билд**.

В результате один и тот же экран одновременно показывает две разные версии:

- hero-чип берёт `PackageInfo.fromPlatform()` → правильная версия
- заголовок таба «История» берёт `AppConstants.appVersionWithPrefix` → **v3.49.2**
- `showLicensePage(applicationVersion: AppConstants.appVersion)` → **3.49.2**

### История версий — выдумана и захардкожена

В `_buildChangelogTab` три «прошлых релиза» заданы константами: `v2.1.0` (июнь 2026), `v2.0.5` (март 2026), `v2.0.0` (январь 2026). Текущий релиз помечен июлем 2026.

То есть по экрану выходит, что за месяц проект прошёл путь от 2.0.0 до 3.49.2, а вся история 3.x отсутствует. Плюс 6 из 7 пунктов «что нового» — сырые русские строки прямо в коде, среди них:

> «Ультра-плавный движок анимаций (120 FPS без рывков и дерганий списков)»
> 

Это было написано в приложении **до** того, как работы по плавности вообще начались. Ровно тот тип рекламного текста, который запрещён правилами репозитория для `CHANGELOG.md`.

### Самое обидное: рабочий пайплайн уже есть и не используется

`services/update/app_update_service.dart` уже умеет:

- тянуть `pubspec.yaml` с `raw.githubusercontent.com` и доставать актуальную версию
- тянуть `CHANGELOG.md` и разбирать его методом `parseChangelog()` по секциям `## [X.Y.Z]`
- получать размер APK (`apkSize`), дату релиза (`publishedAt`), тег и ссылку

Всё это возвращается в `AppUpdateInfo.changelog` — и экран «О приложении» это игнорирует, показывая вместо реальных данных выдуманный список v2.x.

## 2. Дублирование логики обновления

В приложении два пути проверки апдейта, и экран использует неправильный.

`_checkForUpdate()` внутри экрана создаёт `const AppUpdateService()` напрямую — минуя и `appUpdateServiceProvider`, и `otaUpdateProvider.checkForUpdate()`. Последствия:

- состояние `otaUpdateProvider` после проверки **не обновляется**: карточка продолжает писать «OTA-обновления NiosMess» (idle), хотя апдейт уже найден
- локальный `_isCheckingUpdate` дублирует существующий `OtaStatus.checking`
- `_isCheckingUpdate` блокирует кнопку целиком, поэтому во время проверки нельзя нажать «Установить» для уже скачанного APK

Карточка различает только `downloading` / `readyToInstall` / всё остальное. Из семи состояний `OtaStatus` четыре (`checking`, `available`, `installing`, `error`) невидимы.

Не используется вообще:

- `state.errorMessage` — экран вместо него кидает свой тост с сырым текстом исключения
- `cancelDownload()` — кнопки отмены загрузки нет нигде
- `progress`, `receivedBytes`, `totalBytes` — прогресс показан только текстом «Загрузка: N%», полосы нет
- `apkSize` и `publishedAt` — размер и дата релиза не показываются
- `changelog` с сервера — доступен, но виден только внутри `AppUpdateDialog`

Отдельно: `AppUpdateService.downloadAndInstall()` (~90 строк) — вторая, полностью неиспользуемая реализация загрузки, дублирующая `OtaUpdateNotifier.startDownload()` и пишущая в другой файл (`niosmess_update.apk` против `niosmess_VER.apk`). Мёртвый код.

И `installApk()` при отсутствии файла молча вызывает `startDownload()` — пользователь жмёт «Установить», а начинается скачивание без объяснений.

## 3. Перф: тот самый антипаттерн, который только что чинили

`ref.watch(otaUpdateProvider)` стоит в начале `build()` экрана. А `OtaUpdateNotifier.startDownload()` присваивает новое состояние **на каждый чанк стрима**:

```dart
await for (final List<int> chunk in streamedResponse.stream) {
  state = state.copyWith(progress: currentProgress, receivedBytes: received, ...);
}
```

Итого при загрузке APK весь экран «О приложении» — hero, `FutureBuilder`, `SegmentedButton`, 10 аккордеонов FAQ или весь список changelog — перестраивается сотни раз в секунду. Уведомление в шторке при этом троттлится (650 мс + 3%), а UI — нет.

Чинится в два приёма: троттлинг прогресса в нотифаере (~16–33 мс) и `Consumer` + `.select` только вокруг карточки обновления.

Мелочи рядом: `LayoutBuilder` в `_buildSegmentedTabSelector` не использует `constraints` — мёртвая обёртка с лишним проходом лэйаута.

## 4. Дёрганья и движение

- **`AnimatedSwitcher` без `AnimatedSize`.** Высота табов разная (FAQ с 10 аккордеонами против 4 строк «Документов»), поэтому при переключении контейнер скачком меняет высоту и дёргает скролл. Нужен `AnimatedSize` или `TabBarView` с `PageStorageKey`.
- **Смешанная система кривых:** `switchInCurve: M3SpringCurves.spatial`, `switchOutCurve: Curves.easeInCubic`. Правило репозитория — всегда `M3SpringCurves`.
- **`M3SpringCurves.bouncy` на нажатии логотипа** (`AnimatedScale` 1.0 → 0.92). Овершут на состоянии press ощущается как желе; отскок уместен на отпускании и на входе, для нажатия нужна быстрая spatial-кривая.
- **Выбранный таб не сохраняется** — сбрасывается на «Разработчики» при каждом заходе, на десктопе особенно заметно.

## 5. M3 Expressive: сейчас это не Expressive

Экран состоит из восьми почти идентичных контейнеров: `surface` или `surfaceContainerLow` + рамка `outlineVariant` 1px + радиус 20. Это визуальный язык «список карточек в рамке», а не M3E. Expressive строится на **тональной иерархии и форме**, а не на обводках.

Конкретное:

- **Ручное ветвление темы** `isDark ? surfaceContainerLow : surface` повторяется ~8 раз, плюс захардкоженные альфы 0.28 / 0.35 / 0.45 / 0.5 / 0.6 / 0.65 / 0.7 / 0.75 / 0.85. Тональная система M3 существует именно чтобы этого не делать. Альфа разделителя при этом разная для одной и той же роли: 0.15 в «Документах» и 0.12 в FAQ.
- **Зоопарк радиусов:** 24, 22, 20, 16, 14, 12, 8, 6 — магические числа, при этом в проекте есть `AppRadii` и `AppConstants.cardRadius = 28`, и они здесь не используются.
- **Радуга акцентов:** четыре строки таба «Документы» получают `primary`, `secondary`, `tertiary`, `onSurfaceVariant` без логики. В M3E акцент — это сигнал важности, а не декор. Нужен один нейтральный цвет иконок и один акцент на действительно важном элементе.
- **Баг рамки hero-карточки:** `Material(borderRadius: 24, clipBehavior: Clip.antiAlias)` с вложенным `Container(decoration: border)` того же радиуса — рамка рисуется внутри клипа и на скруглениях подрезается, выглядит тоньше/рвано. Нужно перенести обводку в `shape` самого `Material` либо взять `Card.outlined`.
- **Формы M3E почти не используются.** `M3Container(Shapes.c9_sided_cookie)` только у логотипа. Подпись Expressive — морфинг формы: логотип по нажатию должен менять форму, а не масштаб.
- **`SegmentedButton` перегружен:** 4 сегмента с иконкой и подписью при `fontSize: 11.5` и `maxLines: 1` — на 360 dp подписи гарантированно обрежутся. Нужно 3 сегмента и скрытие иконок под ~400 dp.
- **Выравнивание:** `childrenPadding: fromLTRB(64, ...)` при leading 36 + 16 = 52 (FAQ) и 58 при 12 + 36 = 48 (changelog) — сдвиг на 10–12 px, текст ответа не выровнен с заголовком.
- **Роль разработчика в чипе** `fontSize: 10.5`, `maxLines: 1`, ellipsis — «Руководитель разработки клиента & UX» на телефоне обрежется. Роль надо разрешить в две строки или сократить.
- **Разные брейкпоинты:** таб разработчиков переключается на две колонки при `maxWidth >= 600`, а настройки в приложении используют 760.

## 6. Мёртвое и бессмысленное

- **Тап по логотипу ничего не делает** — `onTap: () { HapticService.tap(); }`. Есть анимация нажатия, есть отклик, нет действия. Готовое место под easter egg.
- **`Icons.verified_rounded` использована дважды не по смыслу:** рядом с версией (верифицированная версия?) и рядом с никами разработчиков — при том что верификация в NiosMess реальная функция (`isVerified` у чатов). Символ со значением использован как украшение.
- **Футер `NiosMess © 2026 • Все права защищены`** — год захардкожен и сгниёт, а «все права защищены» противоречит соседнему разделу «Сторонние лицензии и библиотеки».
- **`placeholderBuilder` у SVG разработчика** с фоллбеком на PNG практически недостижим (ассет из бандла грузится мгновенно) — тройная цепочка фоллбеков вместо одной.
- **Около 30 строк захардкожены по-русски** при живой системе l10n: «Устройство», «Альфа-тест», «Обновление системы», «OTA-обновления NiosMess», «Готово к установке», «Установить», «Прогресс», «Проверить», «Согласие на обработку данных», «Сторонние лицензии и библиотеки», все подзаголовки «Документов», обе роли разработчиков, tooltip, футер, оба тоста. Прямое нарушение правила «все пользовательские строки через `context.l10n`».
- **Сырое исключение в тост:** «Не удалось проверить обновления: (текст ошибки)». Пользователю показывается stack-подобный мусор.
- **Оффлайн не обработан:** кнопка «Проверить» без сети даёт тот же сырой тост. `connectivityProvider` в проекте есть и здесь не используется.
- **Нет `Semantics`** ни на чипах, ни на логотипе, ни на чипе версии (тап = копирование, но об этом знает только зрячий пользователь, увидевший иконку 12 px).
- Рядом в OTA-провайдере: цвет уведомления `Color(0xFF6750A4)` захардкожен (базовый M3-фиолетовый, не следует теме), а `_showPermissionDialog` собран на сыром `AlertDialog` вместо репозиторных `showAppConfirmDialog()` / `showAppDialog()`.

## 7. Чего критически нет

Для альфа-продукта с самодельным OTA это самый ценный блок, и его нет вообще.

| Чего нет | Зачем нужно |
| --- | --- |
| «Сообщить о баге» | В репозитории есть `/chat/direct/support` и `supportRepositoryProvider` — не выведены сюда |
| «Что нового» после обновления | Удалённый changelog уже качается, но после апдейта не показывается |
| Поделиться приложением / инвайт | Есть `AppConstants.webOrigin` и `chatShareUrl` |
| Время последней проверки обновлений | Сейчас непонятно, проверялось ли вообще |
| Размер загрузки и дата релиза | Данные уже есть в `AppUpdateInfo` |
## 8. Предлагаемая структура

1. **Hero.** Логотип с морфингом формы по нажатию (`Shapes.c9_sided_cookie` → другая форма) вместо масштаба 0.92. Имя, tagline, чип версии. Тап — копировать версию.
2. **Карточка обновления.** Единственный источник — `otaUpdateProvider`. Все семь состояний. Детерминированный прогресс через `Md3SquiggleProgress` (он уже есть в репозитории и идеально попадает в M3E), размер APK, дата релиза, кнопка отмены, ссылка «Что нового» из удалённого changelog, время последней проверки. Ошибки — человеческим текстом из `state.errorMessage`.
4. **Табы — три вместо четырёх:** «Что нового», «Документы», «Команда». FAQ переезжает на отдельный экран справки с поиском — это help-поверхность, а не about.
5. **Блок «Помощь и связь»:** поддержка, Telegram-канал, [ni-os.ru](http://ni-os.ru), альфа-тест, поделиться.
6. **Футер:** динамический год, канал сборки, без «все права защищены».

## 9. План по фазам

### Фаза 0. Единый источник версии

Сгенерированный `build_info.dart` (CI пишет version, build, commit, дату, канал) плюс `PackageInfo` в рантайме. `AppConstants.appVersion*` удалить или сделать прокси к `build_info`. Ни одной захардкоженной версии в коде экрана.

### Фаза 1. Changelog из данных

`CHANGELOG.md` положить в ассеты, парсить существующим `AppUpdateService.parseChangelog()`, локальную историю рендерить из разобранных секций. Удалить хардкод v2.1.0 / v2.0.5 / v2.0.0 и семь рекламных строк.

### Фаза 2. Один путь обновления

Экран работает только через `otaUpdateProvider`. Убрать локальный `AppUpdateService` и `_isCheckingUpdate`. Отрисовать все семь состояний, добавить отмену, прогресс-бар, размер и дату, проверку сети перед запросом, человеческие тексты ошибок. Удалить неиспользуемый `AppUpdateService.downloadAndInstall()`.

### Фаза 3. Перф

Троттлинг прогресса в `OtaUpdateNotifier` (~16–33 мс или шаг 0.5%), `Consumer` + `.select` только вокруг карточки обновления, снять `ref.watch` со `build()` экрана, убрать мёртвый `LayoutBuilder`, вынести статические поддеревья в `const`.

### Фаза 4. Поддержка

 «Сообщить о баге» через `supportRepositoryProvider`, ссылка на поддержку `/chat/direct/support`.

### Фаза 5. Реструктуризация

Три таба, FAQ на отдельный экран справки с поиском, `AnimatedSize` вокруг переключателя табов, персист выбранного таба, единый брейкпоинт 760.

### Фаза 6. M3E-визуал

Тональная иерархия вместо восьми одинаковых обведённых карточек, радиусы из токенов, один акцент вместо радуги, морфинг формы логотипа, исправить рамку hero-карточки, выровнять `childrenPadding`, роль разработчика в две строки, обе кривые `AnimatedSwitcher` из `M3SpringCurves`, press-кривая без овершута.

### Фаза 7. Локализация и мелочи

~30 строк в l10n + `flutter gen-l10n`, динамический год в футере, убрать `verified` не по смыслу, добавить `Semantics` на логотип, чип версии и чипы действий.

### Фаза 8. Чистка соседнего кода

`Color(0xFF6750A4)` в OTA-уведомлении → цвет темы, `_showPermissionDialog` → `showAppConfirmDialog()`, убрать мёртвый фоллбек `placeholderBuilder`, `installApk()` при отсутствии файла должен явно сообщать о повторной загрузке.

### Фаза 9. Гарды

- тест: в `settings_about_screen.dart` нет обращений к `AppConstants.appVersion*` и нет литералов вида `v2.`
- тест: changelog разбирается из ассета и содержит текущую версию из `build_info`
- grep-гард: в файле нет русских строковых литералов вне l10n
- grep-гард: нет `ref.watch(` без `.select(` в этом файле

## 10. Критерии приёмки

- `flutter analyze` — ноль ошибок и предупреждений
- версия в hero, в заголовке changelog и на странице лицензий совпадают и равны `pubspec.yaml`
- в истории версий нет ни одной захардкоженной записи
- переключение табов без скачка высоты
- во время загрузки APK перестраивается только карточка обновления (проверяется `debugRepaintRainbow`)
- видны все семь состояний OTA, загрузку можно отменить
- ни одного русского строкового литерала в коде экрана
- бамп версии в `pubspec.yaml` и запись в `CHANGELOG.md` человеческим языком без маркетинга

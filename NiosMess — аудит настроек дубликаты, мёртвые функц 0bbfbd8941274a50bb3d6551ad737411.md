## 1. Диагноз в трёх строках

1. **Экрана настроек как сущности не существует.** Хаб — это `profile_screen.dart`, а список разделов физически продублирован дважды: мобильный через `context.push('/settings/...')` и десктопный через `SettingsSectionId`. У одних и тех же пунктов там разные иконки, разные цвета и местами разные названия.
2. **Нет дизайн-системы настроек.** `settings_ui.dart` даёт три плитки с тремя разными геометриями, фальшивый AppBar вместо коллапсящегося M3, магический отступ разделителя `indent: 58`, семь собственных реализаций нажатия и дубль заголовка на каждом экране. Именно это читается как «дёшево», а не отсутствие украшений.
3. **Примерно треть контролов не работает или врёт**, а «Сбросить все настройки» сбрасывает половину полей и глушит надёжную фоновую доставку.

## 2. Часть A. Почему настройки выглядят дешёво

Это не про «мало градиентов». Это про нарушенные базовые вещи, которые глаз считает признаком дешёвого продукта.

### A1. Фальшивый AppBar вместо M3-заголовка

`SettingsScaffold` создаёт `AppBar` полностью прозрачным, с `elevation: 0`, `scrolledUnderElevation: 0` и единственным кружком «назад», а сам заголовок рисует как `headlineLarge` **внутри списка**. Следствия:

- заголовок уезжает под статус-бар и «слипается» с ним, потому что отступ считается руками: `MediaQuery.paddingOf(context).top + kToolbarHeight + 8`;
- нет коллапса крупного заголовка в компактный при скролле — главный визуальный признак современного M3;
- нет `scrolledUnderElevation` / тональной подложки, контент физически наезжает на строку статуса.

**Фикс:** `SliverAppBar.large` (M3E flexible top app bar) с реальным коллапсом, тональной подложкой `surfaceContainer` при скролле и `pinned: true`. Никаких ручных вычислений safe area.

### A2. Заголовок дублируется на каждом экране

На всех субэкранах одновременно передаются `SettingsScaffold(title: ...)` и `SettingsNavBanner(title: ..., subtitle: ...)` — с **одним и тем же текстом**. Пример: `settings_account_screen.dart` рисует `settingsAccountTitle` дважды подряд. То же в privacy, preferences, chats, storage, language-region, e2ee.

**Фикс:** заголовок живёт только в app bar. `SettingsNavBanner` превращается в опциональный пояснительный блок **без** заголовка — или удаляется, а подзаголовок уходит в `SliverAppBar` как supporting text.

### A3. Три плитки — три геометрии

| Плитка | Иконка | Радиус иконки | Горизонт. паддинг | Стиль текста |
| --- | --- | --- | --- | --- |
| `SettingsTile` | 38×38 | 12 | 12 | `bodyMedium` 14 / w600 |
| `SettingsSwitchTile` | 42×42 | 13 | 14 | `bodyLarge` / w600 |
| `SettingsInfoTile` | 42×42 | 13 | 14 | `bodyLarge` / w600 |

В одной карточке они стоят рядом — текст и иконки не выстраиваются в колонку. Плюс разделители вставляются с жёстким `indent: 58`, тогда как реальная левая граница текста у `SettingsTile` = 12 + 38 + 14 = **64**, а у switch/info = 14 + 42 + 14 = **70**. То есть разделитель не совпадает с текстом ни в одном из трёх случаев.

**Фикс:** один примитив `SettingsListItem` с вариантами (`nav`, `switch`, `value`, `slider`, `danger`), единый слот иконки как токен, отступ разделителя вычисляется из этого токена, а не хардкодится.

### A4. Радиусы и высоты не токенизированы

В `expressive_tokens.dart` уже есть `AppRadii {sm 12, md 20, lg 28, full}` и `AppHeights {40, 48, 56, 64}`. Настройки их почти не используют: `BorderRadius.circular(16)` у плитки внутри карточки с `AppRadii.mdRadius` (20), карточки хранилища — 20, карточки устройства — 24, баннер внешнего вида — 28, кнопки — 12/14/18/26. Шесть разных радиусов на одном пути пользователя.

**Фикс:** только `AppRadii`. Внешняя карточка — `lg`, внутренняя плитка — `md`, чипы — `sm`.

### A5. Цвета иконок в хабе — вне цветовой схемы

В мобильном хабе `profile_screen.dart` иконки раскрашены хардкодом палитры Tailwind: `0xFF3B82F6`, `0xFF06B6D4`, `0xFF8B5CF6`, `0xFF2563EB`, `0xFFF59E0B`, `0xFF10B981`, `0xFFEC4899`, `0xFF14B8A6`, `0xFF0284C7`, `0xFF64748B`. При этом **десктопный сайдбар для тех же строк** использует `scheme.primary/secondary/tertiary`.

Следствия: динамический цвет и seed-палитра игнорируются, в тёмной теме контраст не гарантирован, мобильная и десктопная версии выглядят как два разных приложения.

**Фикс:** только роли `primary` / `secondary` / `tertiary` / `error`. Никакого hex в экранах.

### A6. Движение непоследовательно

В одном экране одновременно: `Curves.easeOutCubic` (в `SettingsTile` и `SettingsSwitchTile`), `M3SpringCurves.bouncy`, `M3SpringCurves.snappy`, `M3SpringCurves.spatial`, `M3SpringCurves.expressiveStandard`. `AGENTS.md` требует пружины `M3SpringCurves` везде, где они есть. Плюс семь независимых реализаций нажатия с разными масштабами:

| Место | Масштаб | Кривая |
| --- | --- | --- |
| `TouchContainer` | 0.975 | `AppMotion.releaseCurve` |
| `_InteractiveBrandBadge` | 0.90 | `bouncy` |
| `_InteractiveSpecTile` | 0.98 | `bouncy` |
| `_ColorOrbItem` | 0.90 | `bouncy` |
| `_RainbowCustomOrbItem` | 0.90 | `bouncy` |
| `_AuthStyleThemeToggleCard` | 0.90 | `snappy` / `bouncy` |
| `_CustomColorPickerSheet` | 0.90 / 0.96 | `snappy` / `bouncy` |

**Фикс:** один `PressableSurface` (или расширенный `TouchContainer`) — единственный способ получить реакцию на нажатие в настройках. Остальные шесть удаляются.

### A7. Нарушения собственного протокола M3E

- `Switch.adaptive` в `SettingsSwitchTile` → на iOS в M3E-приложении появляется купертиновский тумблер. `AGENTS.md` требует M3 `Switch`.
- `LinearProgressIndicator` напрямую в `_AnimatedResourceMeter` (`settings_system_device_screen.dart`) → запрещено, нужен `AppLoadingIndicator`.
- Жёсткие `BoxShadow` там, где протокол требует тональные поверхности: орбы палитры (`blurRadius` 4/8), карточка темы (6), кнопка-кружок (6), превью цвета (8).
- `SettingsTile`, `SettingsSwitchTile`, `SettingsInfoTile` объявлены как `ConsumerStatefulWidget`, но их `State` **пустые** — лишний `StatefulElement` на каждую строку настроек.

### A8. Хардкод русских строк вместо l10n

Полностью без `context.l10n`: `settings_chats_screen.dart` (все строки), `settings_system_device_screen.dart` (все строки), заголовки всех секций хаба в `profile_screen.dart`, лист выбора аватара, тексты `_EditProfileSheet`, «Безопасность и 2FA в Nios ID» в `settings_account_screen.dart`. Английская локаль на этих экранах не работает.

## 5. Часть D. Производительность настроек

### D1. Каждый тик слайдера пишет 26 ключей на диск

`UiSettingsNotifier._persist` выполняет `Future.wait` из **26** операций `SharedPreferences` — при изменении **любого** одного поля. А слайдеры («Закругление сообщений», «Закругление интерфейса», громкость, сила predictive back) вызывают сеттер в `onChanged`, то есть на каждом тике перетаскивания.

Итог: одно движение пальцем = сотни записей на диск и десятки полных перестроений дерева темы.

**Фикс:** писать только изменившийся ключ; слайдеры сохранять в `onChangeEnd` или через дебаунс 250 мс, а промежуточное значение держать в локальном состоянии.

### D2. Вспышка неверных настроек на холодном старте

`UiSettingsNotifier.build()` возвращает `UiSettingsState.defaults()` и запускает `_load()` **без ожидания**. Первые кадры приложение рисует дефолтной темой, дефолтным шрифтом и дефолтным языком, затем резко переключается. Плюс флаг `_loaded` проверяется уже после `await SharedPreferences.getInstance()`, то есть возможна гонка двух `_load()`.

**Фикс:** гидратация настроек до `runApp` (или `AsyncNotifier` с splash-состоянием), проверка `_loaded` до любого `await`.

### D3. Настройки строятся целиком, без ленивости

`SettingsScaffold` использует `SliverList(delegate: SliverChildListDelegate.fixed(listItems))` — все дети создаются сразу. На экране внешнего вида это шейдерный баннер, карточка темы, три слайдера, два тумблера контраста, три пункта навигации и секция обоев одновременно.

**Фикс:** `SliverList.builder` по декларативному списку секций.

### D4. Экран внешнего вида — самый дорогой в приложении

- `AnimatedMeshGradient` (`speed: 2.2`, `amplitude: 28`, `grain: 0.03`) — постоянно работающий фрагментный шейдер на 195 dp.
- `_isTouching` подсветка: `setState` на **каждый** тик `onPanUpdate`, перестраивающий весь `Stack` баннера.
- `DynamicColorBuilder` + `AppTheme.themed(...)` пересчитываются в `build`, а сверху `AnimatedTheme` на 350 мс — при каждом изменении любого тумблера.
- Орбы палитры: `AnimatedScale` + `AnimatedContainer` + `BoxShadow` на каждый из девяти элементов в горизонтальном `ListView`.

**Фикс:** шейдер только при tier A и только пока экран видим; подсветку касания вынести в `ValueNotifier` + `RepaintBoundary` без `setState`; тему считать в `select`-производном провайдере, а не в `build`.

### D5. Экран устройства анимирует то, что не должно анимироваться

Два `_AnimatedResourceMeter` форматируют строки внутри `AnimatedBuilder` на каждом кадре 900 мс, плюс три больших карточки прогоняются через `flutter_animate` `.animate().fade().slideY()`. Для экрана со статичными ТТХ это чистые потери.

### D6. Десктопный master-detail перестраивает раздел целиком

`AnimatedSwitcher(260 ms)` + `FadeTransition` + `SlideTransition` вокруг `KeyedSubtree`, а внутри каждый встроенный экран имеет собственный `LayoutBuilder` и `CustomScrollView`. Каждое переключение раздела — полный релэйаут.

### D7. Прочее

- `TouchContainer` по умолчанию `clipBehavior: Clip.antiAlias` → save-layer на каждую строку настроек.
- Выбор часового пояса: `ListView.separated(shrinkWrap: true)` внутри `ConstrainedBox`, фильтрация всего списка зон на каждое нажатие клавиши, полное перестроение модалки через `StatefulBuilder`.
- `settings_privacy_screen` открывает подэкраны сырым `Navigator.push(MaterialPageRoute)` вместо `context.push` — ломает диплинки, тему переходов страниц и predictive back.
- Два независимых снимка хранилища (см. B13).

## 6. Часть E. Чего критично не хватает

## 8. Часть G. Единый слой компонентов

Это основа всей реструктуризации. Без неё правки снова расползутся.

### G1. Декларативный реестр настроек

Один источник истины, из которого генерируются мобильный список, десктопный master-detail и индекс поиска:

```dart
sealed class SettingsNode {
  final String id;              // стабильный, для диплинков и аналитики
  final String Function(AppLocalizations) title;
  final String Function(AppLocalizations)? subtitle;
  final IconData icon;
  final SettingsGroup group;
  final bool Function(SettingsContext)? availability; // kIsWeb, Platform.isAndroid, флаги
}

final class SettingsNav extends SettingsNode { final String route; }
final class SettingsToggle extends SettingsNode { /* selector + onChanged */ }
final class SettingsChoice<T> extends SettingsNode { /* segmented / radio */ }
final class SettingsSlider extends SettingsNode { /* min, max, divisions, unit */ }
final class SettingsAction extends SettingsNode { /* destructive */ }
```

Это автоматически убивает B1 (два списка), B9 (четыре проверки `kIsWeb`) и делает поиск тривиальным.

### G2. Примитивы UI

| Компонент | Ответственность | Ключевые правила |
| --- | --- | --- |
| `SettingsShell` | `SliverAppBar.large`  • поиск + сливеры | никаких ручных safe area, `SliverList.builder` |
| `SettingsGroupCard` | секция с заголовком | `surfaceContainerLow`, `AppRadii.lgRadius`, отступ разделителя из токена слота иконки |
| `SettingsListItem` | все строки | один слот иконки, один стиль текста, минимум 56 dp, варианты `nav / switch / value / slider / danger` |
| `PressableSurface` | единственная реакция на нажатие | `M3SpringCurves.spatial`, `Clip.none`, один масштаб |
| `SettingsPreviewCard` | живое превью геометрии | реальный `MessageBubble`  • реальная карточка |

### G3. Правила, обязательные к соблюдению

- Цвета иконок — только роли схемы. Hex запрещён.
- Радиусы — только `AppRadii`. Высоты — только `AppHeights`.
- Кривые — только `M3SpringCurves`. `Curves.easeOutCubic` и `Curves.easeOutBack` в настройках запрещены.
- `Switch` вместо `Switch.adaptive`. `AppLoadingIndicator` вместо любых `*ProgressIndicator`.
- Тени — только тональные поверхности, никаких `BoxShadow`.
- Все строки — через `context.l10n`.
- Навигация — только `context.push` / `context.go`. Сырой `Navigator.push` запрещён.
- Трёхзначные выборы (тема, фоновый режим, уровень анимаций) — `SegmentedButton` или радиогруппа, никогда не два тумблера.

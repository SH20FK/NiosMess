### МЕД-1. Открытие чужого профиля без существующего чата = вечный шиммер

Закрываю свой прошлый неподтверждённый пункт СТР-4. `profile_shared_media_tab_view.dart`:

```dart
if (widget.chatId == null) {
  // While resolving the chatId, show an elegant shimmer grid
  return _buildShimmerGrid(scheme);
}
if (widget.chatId! <= 0) {
  return _buildNoChatPlaceholder(scheme, textTheme);
}
```

Публичный профиль передаёт `chatId: _resolvedChatId`, а `_resolvedChatId` заполняется только если в локальном списке чатов уже есть личный диалог с этим человеком. Для нового контакта он остаётся `null` навсегда — экрана-резолвера больше нет, никто его не выставит. Комментарий «While resolving» описывает механику, которой не существует.

Итог: внизу профиля любого нового человека — **9 пульсирующих серых плиток, бесконечно**. Плюс 9 постоянно работающих контроллеров `flutter_animate` с `repeat(reverse: true)`. Ветка `&lt;= 0` с корректной заглушкой недостижима.

Фикс: `chatId == null` должен показывать `_buildNoChatPlaceholder`, а не шиммер.

### ЛАГ-15. Медиа-табы профиля нарушают правило 7 протокола пять раз

```dart
GridView.builder(
  shrinkWrap: true,
  physics: const NeverScrollableScrollPhysics(),
  ...
  itemCount: items.length,   // может быть 300+
```

Протокол в корневом `AGENTS.md`, правило 7 — «No unbounded `shrinkWrap: true`». Здесь это `_buildShimmerGrid`, `_buildMediaGrid`, `_buildVoiceList`, `_buildFilesList`, `_buildLinksList` — все пять с `shrinkWrap: true` и `NeverScrollableScrollPhysics`, и все внутри `SliverToBoxAdapter` публичного профиля.

`shrinkWrap` означает, что сетка измеряет **все** элементы за один layout-проход. Для чата с 300 фотографиями это 300 полных layout за один кадр при каждом открытии профиля. Ленивость слайвера уничтожена полностью.

Поверх этого `AnimatedSwitcher` на 200 мс между табами держит **две** такие сетки одновременно.

Фикс: отдать содержимое табов в родительский `CustomScrollView` как настоящие слайверы (`SliverGrid` / `SliverList`), убрать `shrinkWrap`.

### ФЕЙК-1. Поддельный прогресс скачивания файла

`_SharedFileTileState._startDownload`:

```dart
// Smooth simulated progress while download stream progresses
for (double p = 0.15; p <= 0.85; p += 0.15) {
  if (!mounted || !_isDownloading) break;
```

## Список чатов

**ЧАТ-39. `findChildIndexCallback` не срабатывает никогда.**

```dart
return RepaintBoundary(child: item);   // ← у возвращаемого виджета НЕТ ключа
...
findChildIndexCallback: (Key key) {
  if (key is! ValueKey<String>) return null;
  ...
}
```

`SliverChildBuilderDelegate` передаёт в `findChildIndexCallback` ключ **того виджета, который вернул builder**. Здесь это `RepaintBoundary` без ключа. `ValueKey('chat_...')` висит на `Dismissible` глубже, `ValueKey&lt;int&gt;` — на `ChatTile` ещё глубже. Значит колбэк мёртв, и при каждой переупорядочке списка (то есть на каждое входящее сообщение) элементы пересоздаются вместо переиспользования.

При этом правило 3 протокола («Strict O(1) list index resolution») формально соблюдено — `idToIndex` есть. Только он никому не отдаётся. Плюс сам колбэк на горячем пути делает `replaceFirst` + `int.tryParse`, то есть аллокацию строки; правильно вынести ключ наружу как `ValueKey&lt;int&gt;(chat.id)`.

**ЧАТ-40. Свайп «удалить» — это три шага и один пункт меню.**


Фон свайпа показывает иконку корзины и слово «Удалить», но свайп открывает bottom sheet, в котором **ровно одно** действие — «Удалить», а оно открывает ещё и диалог подтверждения. Три взаимодействия там, где обещано одно. Шит с единственным пунктом не нужен: свайп должен вести прямо к подтверждению.

**ЧАТ-43. `RefreshIndicator` вместо `AppLoadingIndicator`.** Стандартный материаловский круг из M2 — в списке чатов, в контактах и в профиле. Правило репозитория: «`AppLoadingIndicator` only».

**ЧАТ-44. Четыре слоя жестов на строку.** `Dismissible` → `GestureDetector(onSecondaryTapDown)` → `TouchContainer` внутри `ChatTile` (свой tap + longPress + анимация нажатия) → `MouseRegion`. ## Медиа-табы профиля

**МЕД-2. Открытие профиля тянет до 600 сообщений.**

```dart
final int added = await ref.read(chatMessagesProvider(cid).notifier).loadOlder(pageSize: 300);
...
if (added >= 280 && mounted) {
  await ref.read(chatMessagesProvider(cid).notifier).loadOlder(pageSize: 300);
}
```

Два запроса по 300 сообщений просто чтобы показать сетку превью внизу профиля. Для этого нужен отдельный серверный эндпоинт медиа-истории, а не выкачивание переписки.

**МЕД-3. Четыре полных прохода по всем сообщениям на каждый билд.** `_buildContent` каждый раз заново считает `_extractPhotosAndVideos(messages)` (со `split(',')`, `toLowerCase()` и детектором типов на каждый URL), `.where(_isVoiceOrVideoNote)`, `.where(_isFile)` и `.where(_hasLink)` (regex по тексту). При 600 сообщениях это четыре прохода с аллокациями — и он вызывается заново при каждом тапе по табу, потому что `_tabController.addListener(() =&gt; setState(() {}))`. Ничего не кешируется.

**МЕД-4. Агрессивный префетч всех фотографий чата.** `_startGroupedBatchPipeline` → `WsMediaFetcher.prefetchBatch(concurrency: 8)` группами по 12, пока не скачает **все** изображения переписки. Запускается автоматически при открытии профиля, без учёта настройки автозагрузки, которую `WsCachedImage` в других местах уважает (`autoDownloadAllowedProvider`). На мобильном интернете это молчаливая выкачка всей галереи.

**МЕД-5. Бесконечные анимации на плейсхолдерах.** И в шиммер-сетке, и в `placeholder` каждой плитки: `.animate(onPlay: (c) =&gt; c.repeat(reverse: true)).fade(...)`. По одному вечному контроллеру на плитку, и они не останавливаются, когда плитка загрузилась вне экрана.

**МЕД-6. `'MP4'` на каждом видео.** Бейдж формата захардкожен строкой, независимо от реального контейнера.

**МЕД-7. Выдуманная длительность.** `durationSeconds: m.mediaDuration ?? 30` и `durationText = ... : '0:30'`. Если сервер не отдал длительность, пользователю показывается «0:30», как будто это факт.

**МЕД-8. `launchUrl` в обход `AppUrlLauncher`.** Вкладка «Ссылки» открывает всё через `launchUrl(uri, mode: LaunchMode.externalApplication)`. Второй нарушитель после строки Nios ID (ПРФ-6) — те же самые «выкидывает в браузер».

**МЕД-9. `ScaffoldMessenger.showSnackBar` вместо `AppToast`.** Плюс текст ошибки — `'Ошибка скачивания файла: $e'`, то есть сырое исключение в лицо пользователю.

**МЕД-10. `DateFormat` без локали.** `DateFormat('d MMM, HH:mm')` и `DateFormat('d MMMM, HH:mm')` — три места. Рядом в публичном профиле корректно: `DateFormat.yMMMMd(currentLocale)`.

**МЕД-11. `TabController` используется как хранилище целого числа.** Создаётся `TabController(length: 4)`, на него ставится слушатель с `setState`, а `TabBar`/`TabBarView` не используются вообще — вместо них самодельные пилюли и `switch` по `_tabController.index`. Значит нет свайпа между табами и нет сохранения позиции скролла. Проще заменить на `int _tabIndex`, либо взять настоящий `TabBarView`.

**МЕД-12. `_MediaGridTileWrapper` — `setState` на каждое событие указателя** и смена кривой прямо во время анимации (`curve: _isPressed ? snappy : bouncy`), что даёт рывок при отпускании. В проекте для этого есть `TouchContainer`.

## Контакты

**КОНТ-1. Запись в кеш внутри `build`.**

```dart
final List<ApiChatSummary>? freshChats = chatsAsync.value;
if (freshChats != null) {
  final direct = _recentDirectChats(freshChats);
  _cachedDirectContacts = direct;
  ref.read(cacheServiceProvider).saveContacts(direct);   // ← I/O в build
}
```

`_buildContactsTab` вызывается из `build`. Правило 6 протокола, и это запись в хранилище на каждый ребилд экрана.

**КОНТ-2. Лишний хоп на каждом переходе к человеку.** Карточка контакта, плитка результата поиска и пункт «Информация о контакте» — все три ведут на `/contact/${username}`, который в роутере объявлен как `redirect` на `/profile/:username`. То есть каждый переход к профилю проходит через промежуточный маршрут. Надо сразу `/profile/`.

**КОНТ-3. Звонок из контактов теряет имя и аватар.** Все четыре кнопки звонка используют `/call/dm/${username}?isVideo=0|1`, а этот маршрут собирает `OutgoingCallArgs` только из `username` и `isVideo` (РОУТ-7). Экран исходящего звонка показывается с пустым именем и без аватара, хотя и то и другое есть в `ApiChatSummary` прямо в момент нажатия. Передавать через `extra`, как это делает публичный профиль.

**КОНТ-4. `ref.watch(uiSettingsProvider)` целиком + десять `ref.read(uiSettingsProvider).haptics`.** Полный watch всего объекта из 30 полей в `build`, плюс в каждом обработчике повторное чтение всего состояния только чтобы узнать один `bool`. Нужен `.select` и один локальный `hapticsEnabled`.

**КОНТ-5. Звезда «в избранном» в шите не обновляется.** `isFav` вычисляется **до** открытия bottom sheet и захватывается замыканием, поэтому после тапа иконка не меняется — шит просто закрывается. `Consumer` внутри шита решил бы это.

**КОНТ-6. Табы сделаны `SegmentedButton`-ом.** «Контакты / Звонки» переключаются локальным `_selectedTab`. Нет свайпа, нет сохранения позиции скролла, нет анимации перехода, состояние теряется при пересоздании экрана. И заголовок `AppBar` меняется от того же флага, то есть дублирует выбранный сегмент.

**КОНТ-7. Алфавитная группировка теряет часть алфавитов и не липнет.**

```dart
final String key = RegExp(r'^[A-ZА-ЯЁ]').hasMatch(letter) ? letter : '#';
```

Латиница и кириллица — отдельными буквами, всё остальное (казахский, армянский, иврит, эмодзи, цифры) сваливается в `#`. Заголовки секций — обычные `SliverToBoxAdapter`, а не `SliverPersistentHeader`, поэтому не прилипают при скролле. И на каждую букву создаётся отдельный `SliverList.separated`: для 26 букв это 52 слайвера в одном `CustomScrollView`.

**КОНТ-8. Результаты поиска строятся не лениво.** `SliverChildListDelegate(children)`, где `children` — заранее собранный список всех пользователей, чатов и сообщений с разделителями. Все элементы создаются сразу.

**КОНТ-9. `MyQrCodeSheet.show(context)` вызывается дважды без аргументов** (иконка в `AppBar` и быстрое действие «QR-код») — здесь это корректно, потому что QR свой. Но тот же виджет используется публичным профилем с чужими данными и остаётся подписанным «Мой QR-код» (ПРФ-7).

**КОНТ-10. Около двадцати захардкоженных строк:** `'Звонки'`, `'Контакты'`, `'Мой QR-код'`, `'Добавить контакт'`, `'Новый контакт'`, `'Поиск пользователя'`, `'QR-код'`, `'Добавить'`, `'Избранные'`, `'Все контакты'`, `'Открыть чат'`, `'Голосовой вызов'`, `'Видеозвонок'`, `'Информация о контакте'`, `'Позвонить'`, `'Удалить из избранных'`, `'Добавить в избранное'`, `'Чат'`.

## Публичный профиль

**ППРФ-1. «Отключить уведомления» не делает ничего.**

```dart
bool _isMutedLocally = false;
...
setState(() { _isMutedLocally = !_isMutedLocally; });
AppToast.showSuccess(context, ... profileMuteNotifications);
```

Чисто локальный флаг в `State`. Ни запроса, ни `chatMutedProvider`, ни сохранения. Показывается тост «успешно», экран закрывается — и всё забывается. При этом рабочий `chatMutedProvider` в проекте есть и используется в канале.

**ППРФ-2. «Общие группы» показывают все твои группы.**

```dart
final commonGroups = allChats.where((c) => c.chatType != 'direct').toList();
...
...commonGroups.take(6).map(...)
```

Никакого пересечения с участником не вычисляется — это просто список всех твоих не-личных чатов, обрезанный до шести. То есть экран уверенно врёт: «у вас есть общие группы», которых нет. Либо серверный эндпоинт, либо убрать пункт.

**ППРФ-3. Жалоба уходит с `chatId: 0`.** `_submitUserReport` вызывает `report(chatId: _resolvedChatId ?? 0, ...)`. Для человека, с которым нет диалога (самый частый случай жалобы), уходит нулевой chatId, а пользователю показывается «жалоба отправлена».

**ППРФ-4. Ошибка «Написать» никак не показывается.** `_handleMessageTap` при неудаче ставит `_messagePhase = ActionPhase.error` — и на этом всё: `_messagePhase` используется в UI только для показа спиннера при `pending`. Состояние `error` не отображается нигде, кнопка просто перестаёт грузиться. Нет ни тоста, ни повтора.

**ППРФ-5. `profile.id == 1` как признак поддержки.** `isSupport = username.toLowerCase() == 'support' || profile.id == 1`. Захардкоженный идентификатор в клиенте, плюс третья независимая проверка «это поддержка» (см. ЧАТ-36).

**ППРФ-6. Время «был(а)» пишется латиницей.** `'${l10n.profileLastSeen} ${diff.inMinutes}m'` и `'... ${diff.inHours}h'`. В русском интерфейсе — «был(а) 5m». Единицы нужно локализовать.

**ППРФ-7. Двойной редирект на свой профиль.** `_checkCacheAndLoad` сначала делает postFrame `context.go('/main/profile')`, а затем `_loadProfile` независимо делает `context.go('/main/profile')` ещё раз после сетевого ответа. Второй `go` может сработать уже после ухода со страницы.

**ППРФ-8. Смешение реактивного и статического радиуса в одном файле.** `AppRadii.xlRadius` и `AppRadii.mdRadius` — статические константы, не реагируют на настройку скругления, при этом `AppRadii.fullRadius` на главной кнопке — тоже статический. Экран целиком игнорирует ползунок. Это АРХ-2 в конкретном месте.

**ППРФ-9. `maxWidth: 840` числом** вместо `Breakpoints.medium`, который равен ровно 840 и лежит в том же импортированном файле.

## Архитектура (продолжение)

**АРХ-13. Файлы-призраки и дубли в `lib/widgets/chat/`.** `chat_list_tile.dart` (194 B) — `typedef` + реэкспорт `chat_tile.dart`. Рядом `chat_list_filter_bar.dart` (430 B) и `chat_search_field.dart` (595 B) того же вида, при том что есть полноразмерные `chat_filter_bar.dart` (5 371) и `chat_search_bar.dart` (28 260). Итого две «панели фильтров» и два «поиска» с пересекающимися именами.

**АРХ-14. `ws_cached_image`: декодирование без кеша и удержание байтов.** `Image.memory(_bytes!)` без стабильного ключа кеша означает повторный декод при каждом создании виджета, а сами `Uint8List` висят в `State` каждого экземпляра, пока он в `cacheExtent`. В медиа-сетке профиля это десятки полных изображений в памяти одновременно.

**АРХ-15. `ws_cached_image` на web может ломать медиа.** `_tryLocalFile` для любого пути без схемы возвращает `File(path)` через `universal_io`, затем `await local.exists()` внутри общего `try`. На web это уходит в `catch` и превращается в состояние ошибки вместо загрузки через WebSocket. Нужен явный `if (kIsWeb)`. Помечаю как требующее проверки на web-сборке.

**АРХ-16. Нет остановки медиа за пределами экрана.** Ни `_StickerVideoPlayer`, ни `_CircleVideoInlinePlayer` не используют `VisibilityDetector` или аналог: анимированные стикеры играют всегда, как только были инициализированы.

**АРХ-17. No-op слои в инпут-области.** `Container(color: Colors.transparent)`, внутри которого `DecoratedBox(decoration: BoxDecoration(color: Colors.transparent))`. Два уровня дерева, которые ничего не делают.

**АРХ-18. `_showOverflowMenu => true` и `heroTag` в никуда.** В `ChatDetailAppBar` — геттер-константа. В `M3SpeedDialFab` параметр `heroTag` объявлен, передаётся из шелла как `'compose_chat_fab'` и **нигде не используется**, потому что это не настоящий `FloatingActionButton`.

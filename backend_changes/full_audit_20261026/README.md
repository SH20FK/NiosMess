# Проверки серверных исправлений от 26.10.2026

Оба исправления **согласованы владельцем и уже развёрнуты**. Это воспроизводимый пакет исходников и проверок для Git/CI. Он не подключается к серверу, не устанавливает патчи и не читает production-конфигурацию или переписки.

## Что сохранено

| Исправление | Файлы сервера | Эффект |
|---|---|---|
| Изоляция звонков | `app/ws/handlers/call_handler.py` | Связь room/chat/message, проверка реального членства, повторная проверка после await, запрет замены чужой комнаты, reservations для параллельных start; проверки legacy get/answer/end |
| Проверка видео-эмодзи | `app/services/public_media_uploads.py`, `app/ws/handlers/media_handler.py` | Реальные размеры, длительность и тип из ограниченного ffprobe вместо доверия клиентским метаданным; отклонение повреждённых и недопустимых файлов до постоянной записи |

API-поля и схема БД не менялись; миграций нет. Установленные ранее эмодзи и переписки не удаляются. Здесь не обещается физическая передача Android RTP или работа всех кодеков.

- `candidate/app/...` — три полных исходника **ровно с SHA-256 развёрнутых файлов**, проверенные root после рестарта. Это проверяемый код патча, не новая переписанная реализация.
- `patches/` — исходные два согласованных unified diff. Они предназначены только для полного исходного дерева с совпадающими before SHA. Повторное применение к уже исправленному серверу не требуется.
- `fixtures/` — только verbatim AST-функции исходного call handler, `_require_member`/`_can_send` и исходного `validate_image`; полный ORM schema-файл нужен настоящему SQLAlchemy mapper из-за связей/ForeignKey. **Это схема без записей**, не выгрузка БД. Её импорты ограничены enum/datetime/sqlalchemy; локальная проверка строковых литералов не обнаружила credential literals. `app.config` и `.env` отсутствуют.
- `manifest.json` — before/after SHA, SHA содержимого пакета, AST fingerprints выбранных исходных функций и результат локальной проверки литералов. Хеши candidate совпадают с записью выполненного deployment; адреса подключения, ключи и production-данные в manifest не нужны.
- `tests/` — авторские проверенные тесты proposals; изменены **только явно перечисленные относительные привязки fixture/candidate путей**. Тело видео-валидатора и сценарии не переписаны.
- `evidence/` — исходное воспроизведение 5 ошибок доступа и исходные результаты 15/11 проверок. Абсолютные локальные пути в video-логе обезличены. Они не заменяют новый запуск CI.

## Запуск CI с Python 3.10

Локальная `.gitattributes` сохраняет байты всего пакета без преобразования LF/CRLF, чтобы `core.autocrlf` не ломал SHA при commit/checkout. Локальная `.gitignore` явно сохраняет три evidence-лога вопреки общему правилу `*.log` репозитория. Все эти файлы должны попасть в Git вместе с `manifest.json`.

Linux runner требует `ffmpeg` и `ffprobe` в PATH, включая encoder **libx264** для создания синтетических MP4. На Ubuntu:

```sh
sudo apt-get update
sudo apt-get install --yes ffmpeg
python3.10 -m pip install -r backend_changes/full_audit_20261026/requirements-test.txt
python3.10 -B backend_changes/full_audit_20261026/run_regressions.py
```

На runner с `actions/setup-python` для 3.10 можно использовать `python` вместо `python3.10`. Пакет проверяет SHA/AST до выполнения. Отсутствие ffmpeg/ffprobe завершает runner ошибкой, а не зелёным пропуском проверок. Ни SSH, ни секреты, ни production-БД для CI не требуются. APK эта команда не собирает.

Ожидаемый результат:

1. **15** регрессий candidate calls: настоящая временная SQLite, настоящий SQLAlchemy ORM и функции handlers/access helpers, извлечённые AST без изменения тела. Только внешние уведомления, генерация fixture-токена и opaque fixture encryption заменены; транспорта и реальных аккаунтов нет.
2. **11** проверок video: 9 сценариев синтетических настоящих MP4/ffprobe, включая отмену с очисткой; исходный bypass `validate_image`; синтаксис/маршрут candidate. Файлы создаются только в TemporaryDirectory; NoDatabase запрещает обращения к БД.
3. **5** воспроизведений уязвимого baseline calls на той же одноразовой SQLite. Их успех означает, что исходная ошибка действительно воспроизводится; это не положительный security-результат baseline.

Нельзя запускать общий `unittest discover` по `test_call_access.py`: файл содержит два намеренно противоположных набора — baseline evidence и candidate regressions. `run_regressions.py` запускает каждый в правильном режиме и очищает унаследованный `NIOS_CALL_ACCESS_BASELINE` для candidate.

## Совместимость и пределы

Требование — Python >=3.10. Первичный локальный прогон выполнялся Python 3.12.10; Python 3.10 проверяется отдельно CI, а не объявляется локально проверенным. SQLite здесь одноразовая и без production URL. Полный authenticated WS dispatcher, production concurrency между несколькими worker и Android RTP этими тестами не доказываются. Reservations сохраняют существующую process-local архитектуру active_calls.

Нужен отдельный rollout для дальнейших изменений. При откате этих исправлений возвращают исходные три файла из проверенной резервной копии и перезапускают сервис после разрешения владельца; БД и историю не откатывают. Возврат старых файлов возвращает и описанные проверки доступа/медиа к прежнему поведению.

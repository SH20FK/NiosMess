# Secret chat protocol 2

8 октября 2026 серверный релиз `/opt/niosmess/releases/secret-chats-v2-20261008` активирован после 11 проверок на отдельной БД. HTTP и добавленная схема проверены после перезапуска. Резервная копия остаётся на сервере с ограниченным доступом.

Этот пакет изменяет копию действующего релиза `/opt/niosmess/current`, включая реальные обработчики `app/ws/router.py`. Старый `ws_manager.py` не используется.

`stage_remote.py` копирует текущий релиз, применяет `apply.py`, проверяет Python и запускает `test_secret_delivery.py` на отдельной SQLite БД. Тестовые зависимости устанавливаются только в каталог проверок. `activate_remote.py` делает согласованную резервную копию БД через SQLite Backup API, атомарно переключает симлинк, перезапускает сервис и проверяет HTTP и схему. При сбое возвращает предыдущий код. SSH-данные читаются из корневого `.env` и не выводятся.

Миграция добавляет таблицы событий, операций, возможностей устройств, курсор старой истории и nullable-поля `messages.client_message_id`, `users_fcm_tokens.session_id`. Обычные сообщения не требуют ID нового протокола. Секретная отправка требует двух клиентов с протоколом 2; старые форматы доступны для чтения. Повторы проверяются до загрузок, счётчиков и уведомлений; подтверждение следует после commit.

## Проверки

- Клиентские сценарии очереди и интерфейса включены в `pulse_flutter/test/suite_test.dart`, который выполняет существующий CI.
- Сервер: `PYTHONPATH=<test-deps>:<patched-release>:<patched-release>/tests SECRET_KEY=test-only ENCRYPTION_KEY=00000000000000000000000000000000 DATABASE_URL=sqlite+aiosqlite:// python -m pytest test_secret_delivery.py -q`.
- Два клиентских экземпляра: запустить `serve_isolated.py 5199` с patched-release и tests в PYTHONPATH, затем `SECRET_CHAT_INTEGRATION_URL=http://127.0.0.2:5199 flutter test test/integration/secret_chat_backend_test.dart`. Сервер использует настоящие обработчики WebSocket и новую отдельную БД; заменена только авторизация двух тестовых аккаунтов. Он слушает только loopback.
- При отсутствии переменной окружения сетевой тест пропускается, чтобы CI никогда не отправлял сообщения на рабочий сервер.

## Откат

Вернуть `/opt/niosmess/current` на `/opt/niosmess/releases/nios-apps-endpoint-20261005` и перезапустить `niosmess.service`. Дополнительные таблицы и поля оставить: старый код их игнорирует. Новый клиент остановит доставку при недоступном `secret_sync`, сохранив журнал и подготовленные пакеты; отправки открытым текстом нет. БД из резервной копии автоматически не восстанавливается, чтобы не уничтожить сообщения, поступившие после выпуска.

При подтверждённом выходе клиент удаляет историю, очередь, вложения и ключи разговоров выбранного аккаунта. В защищённом системном хранилище остаётся идентичность устройства, чтобы повторный вход мог создать новую сессию с тем же устройством. История собеседника не удаляется.

Истечение авторизации останавливает отправку и очищает временные расшифрованные файлы, сохраняя журнал и очередь до повторного входа в тот же аккаунт. Черновики секретных чатов хранятся в журнале; неизвестный тип чата не допускает обычную отправку, загрузку файла или передачу текста внешнему ИИ.

Физические телефоны к рабочей среде не подключены. Проверены два клиентских экземпляра с реальным WebSocket-обработчиком и Hive, а также RU/EN интерфейс на ширине 320 px при 200% шрифте в светлой и тёмной темах. Полный старый набор содержит три ранее известные ошибки текстовых проверок входных экранов (`entry_screens_reachability_test.dart`), которые не относятся к новым сценариям секретных чатов.

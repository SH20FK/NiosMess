# Nios SDK: серверная интеграция

Реализация находится в [backend_changes/protocol_v1](../../backend_changes/protocol_v1/README.md).
Она добавляет `/v1/...` к существующему FastAPI origin `https://ni-os.ru`.
Новый домен, независимые узлы и отдельный сервер ретрансляции не требуются.
Первоначальное предложение сохранено отдельно в [архиве](DEPLOYMENT_PROPOSAL.md).

## Что подключено в приложении

Нативный клиент регистрирует Stream v1 после привязки прежнего X25519 ключа к
сессии. Затем сообщает поддержку в `set_public_key`; `secret_sync` возвращает
возможности конкретного устройства собеседника. Новые вложения используют
сегментный формат только при поддержке обоих устройств и сервиса.

Видео, кружки и голосовые получают локальный capability URL. Плеер запрашивает
диапазоны, клиент скачивает нужные ciphertext-сегменты, проверяет hash и AEAD и
передаёт проверенный plaintext в RAM. На диске остаются ciphertext и bitmap
докачки. AES и segment hashing выполняются в ограниченном фоновом worker.
Выход из аккаунта отменяет потребителей и ждёт их завершения до удаления данных.

Сохранение/отправка файла через системный диалог и PDF preview могут требовать
временный plaintext-файл; владелец удаляет его после завершения действия или
выхода. Это отдельное явное действие, обычное проигрывание его не использует.

Старые вложения остаются читаемыми. Для старого/web-собеседника сохраняется
прежний зашифрованный маршрут. Уже подготовленный Stream-файл не превращается
в старый формат при ошибке. Повтор upload отправляет тот же immutable ciphertext
целиком; чтение, перемотка и докачка выполняются по сегментам.

## Другие серверные модули

- Link: постоянный mailbox, device signatures, дедупликация и cursor sync.
  Production принимает новые операции только в разрешённой secret/MLS сессии;
  неизвестный session domain отклоняется. ACK относится к существующей обратной
  операции. Ответ сервера подтверждает хранение, а не прочтение собеседником.
- MLS: настоящие OpenMLS clients, постоянная reservation до изменения локального
  epoch, exact retry, ordered Commit/Welcome inbox и проверка состава перед
  каждой доставкой. Потерянный coordinator не заменяется по таймеру.
- Iroh: подписанный обмен короткоживущими native Postcard-адресами, pin EndpointId
  и Link key, явный allowlist relay URL. Сервер адресов не является relay.
- История ключей: подписанные записи, Merkle inclusion/consistency proofs и
  постоянный log key. Независимых witnesses нет; полный независимый trust
  profile не включён и SDK witness quorum не ослаблен.

Эти SDK/API доступны отдельно от Flutter UI. Приложение автоматически включает
только Stream v1; массовый перевод существующих групп/переписок на MLS/Link/Iroh
этот выпуск не выполняет. Наличие библиотеки в APK не объявляется поддержкой
неподключённого протокола.

## Проверка

Серверные тесты используют отдельный SQLite, а проверка host adapter — копию
настоящих действующих обработчиков с подменённой фабрикой isolated DB. CI
использует серверный Python 3.10 и включает реальные HTTP тесты Python ↔ Dart
для Stream, MLS и Iroh. Native OpenMLS и QUIC не подменяются тестовыми шифрами.

Проверка на двух Android и замеры FPS требуют устройств; локальный HTTP/native
тест не подтверждает поведение Android ExoPlayer, iOS ATS или мобильного NAT.
APK собирается в CI. `preview_apk` у Build workflow создаёт артефакт ветки без
публикации общего релиза.
